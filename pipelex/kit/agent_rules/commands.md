# Commands

`make` targets activate the virtual environment themselves; anything else (`pytest`, `pipelex`, `pipelex-dev`) runs from `.venv/bin/` (`.venv\Scripts\` on Windows), never bare. The Makefile is the reference for every target and alias; without `make`, read the target there and run its prerequisites one by one.

- **`make agent-check` after every code change, and fix everything it reports.** Its prerequisites are `fix-unused-imports fix-keyword-only format lint pyright mypy check-ledger check-keyword-only check-hub-layering check-rich-imports check-actions-allowlist drift-check api-agent-check`: the import and keyword-only fixers, ruff, pyright, mypy, `plxt` over TOML/MTHDS/PLX, the migration-ledger replay (`cl`), the hub-layering check, the Rich import check (`cri`: Rich is the `cli` extra, so no module outside `pipelex/cli/` imports it at module level or reaches it through a CLI module), the Actions allowlist check (`caa`: every workflow action must be one `.github/actions-allowlist.toml` allows), the drift contracts, and the server's own gate. The drift digest reads the git index, so stage your changes before the check.
- **The Pipelex API server is the `api/` workspace member** (the `pipelex-api` distribution, package `pipelex_api`; its guide is `api/CLAUDE.md`). It runs the pipelex of the same commit from its own environment, `api/.venv`, which its targets provision themselves. `make agent-check` ends with `api-agent-check` (`make -C api agent-check`: its install, ruff, pyright, mypy, and the drift checks of its OpenAPI artifact and of its vendored inference tree) and `make agent-test` with `api-agent-test`, so a library change that breaks the server, moves its wire or leaves its inference tree behind fails in the same change. A kit change reaches the server's tree through `make up-kit-configs` (`ukc`); a change to the server's wire is committed with `make -C api openapi-export`.
- **Keyword-only arguments** (the convention is in the standards and in `docs/contribute/keyword-only-arguments.md`): `make check-keyword-only` (`cko`) is the gate, `make fix-keyword-only` (`fko`) inserts the bare `*` where it can — on ungranted subjects too — and reports the shapes it cannot fix, and `make subject-grant FUNC="<path>::<qualname>" RATIONALE="…"` (`sgr`) grants a positional subject. Grant before `make agent-check`, which runs the fixer.
- **Drift contracts.** When `make drift-check` reports an open contract: `make drift-plan`, review and fix the stale targets, `git add` the trigger files, then `make drift-ack CONTRACT=<id> RATIONALE="<verdict>: …"`, the rationale opening with its verdict, `real-catch`, `clean-pass` or `friction`. No bypass flag; "clean-pass: reviewed, no doc change needed" is a legitimate rationale. See `docs/contribute/drift-contracts.md` and the `/drift-review` skill.
- **`make agent-test` at the end of every coding session.** Heartbeat lines while running, full output only on failure; the server's unit tests run after the library's. If it hangs or fails opaquely, `make agent-test-debug` (`atd`) adds stale-process cleanup, an outer timeout and a live log; the methodology is `docs/agents/debugging-hanging-pytest-runs.md`. At intermediate steps in a local setup, running only the relevant tests is fine: `.venv/bin/pytest -x -q tests/unit/path/to/test_module.py`, or `make t TEST=<name>` (pytest `-k` substring matching; `TEST=LF` reruns the last failures). `make tp` / `make test-with-prints` are for a human at a terminal; an agent in the cloud or in a sandbox uses `make agent-test` only.
- **`make test-ts-gates` (`ttg`) after touching anything under `pipelex/codegen/emitters/`, or moving the pinned prettier version.** `make agent-test` does not cover the TypeScript emission: the two gates that read the emitted TypeScript as TypeScript need a node toolchain and skip silently without one. This target provisions a pinned prettier and zod into `.ts-toolchain/` (npm, node >= 22.6) and makes those gates fail instead of skip, as CI does. See `docs/contribute/typescript-emission-gates.md`.
- **`make cleanderived`** when linters or pytest collection get confused after files were erased or moved.
- **`CLAUDE.md` and `AGENTS.md` are generated.** Edit the sources in `pipelex/kit/agent_rules/` (assembled per `pipelex/kit/index.toml`) and run `make rules`; `make check-rules` is the CI gate, and `make agent-check` does not include it.
- **`pipelex-dev`** (`.venv/bin/pipelex-dev --help`) holds the internal generators, most with a `make` alias. `generate-mthds-schema` (`gms`) after modifying `mthds_schema_generator.py`. `generate-error-pages` (`gep`) and `generate-error-identity` (`gei`) after adding, renaming or removing an error class: consumers outside this repo branch on `error_type`, so a rename is a silent wire break that the committed snapshot turns into a reviewable diff. `refresh-graph-ui-sri --mthds-ui-version <v> [--elkjs-version <v>]` when bumping the pinned mthds-ui or elkjs. `trace-input-semantics` when changing the structure blueprint, the structure generator, the schema render or the contract builder (`docs/contribute/trace-input-semantics.md`). `generate-projection-corpus` to rewrite the fixture corpus committed byte-identically in `mthds-js` and `mthds-python` (`docs/contribute/generate-projection-corpus.md`). `drift` carries the drift-contract commands above.
