# Drift Hunt — Stage 0 suspects (triaged pre-screen hits)

Triage of `prescreen-raw.md` (generated by `prescreen.py`; raw stats: 123 pages scanned, ~1,880 claims checked, 45 FAIL rows). Every row below was verified against the actual surface (CLI `--help`, `pipelex/pipelex.toml`, the real MTHDS parser via `pipelex validate bundle` on scratch bundles, the tree, `../pipelex-cookbook`). Verdicts: **CONFIRMED** (mechanical defect, fix in Stage 0), **JUDGMENT** (real question, seed for Stage 1), **FP** (false positive; pattern recorded to tune Stage 1 prompts).

## Confirmed mechanical defects (fixed in Stage 0)

1. **`docs/building-methods/adapt-to-llm-prompting-style-openai-anthropic-mistral.md` — phantom prompting-style keys.** The config example uses `[pipelex.prompting_config.prompting_styles]` keys `gpt4`, `claude`, `llama`; the real keys in `pipelex/pipelex.toml:275` are `openai`, `anthropic`, `mistral`, `gemini` (values are `tag_style` inline tables, not the documented shape — verify at fix time).
2. **`docs/building-methods/pipes/understanding-multiplicity.md` (block at ~line 74) — example fails the real parser.** `[concept]` shorthand (`LineItem = "…"`) followed by `[concept.LineItem.structure]` is a TOML "Cannot overwrite a value" error — reproduced against `pipelex validate bundle`: a user copying the example gets a syntax error. Fix: declare `[concept.LineItem]` with `description = …` before the structure table.
3. **`docs/building-methods/concepts/native-concepts.md` (block at ~line 417) — example fails the real parser.** `prompt = "…"` basic string containing literal newlines — "Illegal character" reproduced against `pipelex validate bundle`. Fix: `"""` multi-line string.
4. **`docs/under-the-hood/image-handling-in-llm-prompts.md` — two dead file paths.** `pipelex/pipe_operators/llm/llm_prompt_spec.py` (now `llm_prompt_blueprint.py`) and `pipelex/pipe_operators/llm/template_image_analyzer.py` (now `pipelex/pipe_operators/shared/template_image_analyzer.py`).
5. **`docs/under-the-hood/init-cli-flows.md` — init no longer ships `mthds_schema.json`.** The page claims `init_config()` copies `mthds_schema.json` to `.pipelex/mthds_schema.json` (three mentions: intro list, table row, reference table). No non-dev code references it; `pipelex/kit/configs/` contains no schema file (only `pipelex-dev generate-mthds-schema` emits `derived/mthds_schema.json`, and `pipelex/kit/paths.py:32` explicitly says kit templates must not reference it). Fix: drop/correct the three mentions.

## False positives (patterns for Stage 1 prompt tuning + prescreen notes)

1. **MTHDS-dialect leniency (largest class — most of the `toml` rows).** The real parser (tomlkit-based) accepts multi-line inline tables, trailing commas, and comments inside inline tables — all illegal in vanilla TOML, so `tomllib` flags them. Verified live: scratch bundles with these shapes pass `pipelex validate bundle`. Affects: `PipeLLM.md` (85, 103, 192), `pipelex-bundle-specification.md` (192, 216), `configure-ai-llm-to-optimize-methods.md` (50, 80 — syntax only), all `docs/cookbook/*` toml rows, `discord-newsletter.md` (30). *Stage 1 note: do NOT flag these; conversely, a claim "this is valid TOML" elsewhere would be its own drift.*
2. **Alternatives-in-one-block.** Blocks showing the same key several times as variants (`output = …` ×3 in `PipeLLM.md` 255, `llm_models = …` ×3 in `test-profile-configuration.md` 96, `inputs = …` ×3 in `understanding-multiplicity.md` 147, `domain = …` ×3 in `domain.md` 54) or ❌/✅ contrast pairs (`refining-concepts.md` 25). Deliberate teaching devices, not copy-paste units.
3. **Decorated/elided pseudo-code.** ✅/❌ emoji-prefixed lines (`domain.md` 64, 72), `...` ellipsis lines in TOML (`pipelex-bundle-specification.md` 31, `test-profile-configuration.md` 42) and in Python call args (`distributed-content-generation.md` 163), partial snippets starting mid-statement (`error-model.md` 179, an `except` block).
4. **Illustrative placeholder paths.** `tests/path/that/failed/` (`debugging-hanging-pytest-runs.md`), `pipelex/some/edited_file.py` (`keyword-only-arguments.md`).
5. **Negative-existence claims.** `docs/404.md` in `docs/CLAUDE.md` — the doc says this file must NOT exist.
6. **Cross-repo / contextual references.** `docs/error-responses.md` in `error-model.md` explicitly names `pipelex-api`'s docs (file exists there — verified); `backends/hello.toml` in `using-inference-plugins.md` is shorthand anchored by the surrounding "`.pipelex/inference/` directory" prose (real cookbook file verified at `.pipelex/inference/backends/hello.toml`).
7. **CLI alias blindness (prescreen limitation).** `plxt fmt` is a documented clap alias of `plxt format` — the harvest only captures primary command names.
8. **Shortcut command forms invisible in `--help` (prescreen limitation — and a near-miss).** `pipelex validate --all --allow-signatures` and `pipelex validate <pipe_code>` (`signature-pipes.md`) were initially "confirmed" dead because `pipelex validate --help` shows only the `method`/`pipe`/`bundle` subcommands with no group-level `--all`. Live execution proves a shortcut layer forwards these to the `pipe` subcommand (exit 0, flags included) — exactly as `docs/tools/cli/validate.md:18` documents. A draft fix was applied and reverted after the fix-time re-verification (D6). *Stage 1 note: never conclude a CLI form is dead from `--help` alone — run it.*
