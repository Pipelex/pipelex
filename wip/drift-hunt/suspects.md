## False positives (patterns for Stage 1 prompt tuning + prescreen notes)

All patterns below were confirmed as false positives by Louis at Checkpoint 0 (2026-07-12), with two amendments: pattern 6 comes with a "minimal references only" policy, and pattern 8's underlying CLI behavior is a real *code* defect, deferred to `deferred-code-findings.md`.

1. **TOML 1.1 vs TOML 1.0 (largest class — most of the `toml` rows).** MTHDS is based on **TOML 1.1**, which legalizes multi-line inline tables, trailing commas, and comments inside inline tables; `tomllib` implements TOML 1.0 and flags them. Verified live: scratch bundles with these shapes pass `pipelex validate bundle`. Affects: `PipeLLM.md` (85, 103, 192), `pipelex-bundle-specification.md` (192, 216), `configure-ai-llm-to-optimize-methods.md` (50, 80 — syntax only), all `docs/cookbook/*` toml rows, `discord-newsletter.md` (30). *Stage 1 note: do NOT flag these — if it passes the real parser, it's good.*
2. **Alternatives-in-one-block.** Blocks showing the same key several times as variants (`output = …` ×3 in `PipeLLM.md` 255, `llm_models = …` ×3 in `test-profile-configuration.md` 96, `inputs = …` ×3 in `understanding-multiplicity.md` 147, `domain = …` ×3 in `domain.md` 54) or ❌/✅ contrast pairs (`refining-concepts.md` 25). Deliberate teaching devices, not copy-paste units.
3. **Decorated/elided pseudo-code.** ✅/❌ emoji-prefixed lines (`domain.md` 64, 72), `...` ellipsis lines in TOML (`pipelex-bundle-specification.md` 31, `test-profile-configuration.md` 42) and in Python call args (`distributed-content-generation.md` 163), partial snippets starting mid-statement (`error-model.md` 179, an `except` block).
4. **Illustrative placeholder paths.** `tests/path/that/failed/` (`debugging-hanging-pytest-runs.md`), `pipelex/some/edited_file.py` (`keyword-only-arguments.md`).
5. **Negative-existence claims.** `docs/404.md` in `docs/CLAUDE.md` — the doc says this file must NOT exist.
6. **Cross-repo / contextual references — policy: minimal references only.** `docs/error-responses.md` in `error-model.md` explicitly names `pipelex-api`'s docs (file exists there — verified); `backends/hello.toml` in `using-inference-plugins.md` is shorthand anchored by the surrounding "`.pipelex/inference/` directory" prose (real cookbook file verified at `.pipelex/inference/backends/hello.toml`). Ruling: a short, named pointer to another repo's own docs is fine; anything more (workspace-relative paths a docs reader can't resolve, restating another repo's content at length) is drift to fix — inline the short essence here, leave the detail in its home repo (the `codegen-projections.md` fix is the worked example).
7. **CLI alias blindness (prescreen limitation).** `plxt fmt` is a documented clap alias of `plxt format` — the harvest only captures primary command names.
8. **Shortcut command forms invisible in `--help` (prescreen limitation — and a near-miss).** `pipelex validate --all --allow-signatures` and `pipelex validate <pipe_code>` (`signature-pipes.md`) were initially "confirmed" dead because `pipelex validate --help` shows only the `method`/`pipe`/`bundle` subcommands with no group-level `--all`. Live execution proves a shortcut layer forwards these to the `pipe` subcommand (exit 0, flags included) — exactly as `docs/tools/cli/validate.md:18` documents. A draft fix was applied and reverted after the fix-time re-verification (D6). *Stage 1 note: never conclude a CLI form is dead from `--help` alone — run it.* Ruling: the docs are a false positive, but the help-surface invisibility itself is **not OK** — it's a code defect (`pipelex/cli/commands/validate/app.py` bypasses the rewrite on `--help`), deferred to `deferred-code-findings.md` per the fix-in-code-not-docs rule.
