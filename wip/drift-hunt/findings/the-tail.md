### `get-started/mthds-language-tutorial.md` — 1 finding *(found by the post-run false-negative check, not by the wave — hence out of the worst-first order above)*

**F13 · 🟠 wrong**
- **Doc:** `docs/get-started/mthds-language-tutorial.md:166`
- **Claim:** "**`$topic`** — references an input variable in the prompt (**as opposed to `@variable` which references data from working memory**)." The two sigils are taught as distinguished by **where the data comes from**: `$` for inputs, `@` for working memory.
- **Reality:** **The rule is false.** The real distinction is **rendering shape**, not provenance: `@var` (which must sit alone on its own line) is a *block insertion* → `{{ var|tag("var") }}`; `$var` (inline) is an *inline scalar substitution* → `{{ var|format() }}`. Both sigils resolve against the **same** `declared_inputs` set. And declared inputs *are* working-memory entries — there is no separate "input" pool for `$` to be special about. A reader is taught they cannot use `@` on a declared input, which is simply wrong.
- **Code evidence:** `pipelex/cogt/templating/template_preprocessor.py:176-184` (`preprocess_template()`'s docstring: the sigil table above); `pipelex/pipe_operators/llm/pipe_llm_blueprint.py:66-70` (`declared_inputs = set(self.inputs.keys())` — one set feeds *both* sigil passes). The validator's own error text when `@` is used inline on a declared input offers "did you mean `$identifier` … or move `@identifier` onto its own line?" — i.e. `@` on a declared input is not merely legal, it's the expected fix.
- **The tutorial contradicts itself two steps earlier:** Step 2 (`:88`, `:93`) declares `inputs = { story_idea = "Text" }` and then references it as **`@story_idea`** — the exact usage line 166 says is reserved for `$`.
- **Verified — falsified in both directions, empirically:** a scratch bundle declaring `inputs = { topic = "Text" }` and referencing `@topic` on its own line → `Successfully validated bundle`. A scratch `PipeSequence` where `story_idea` comes *purely* from a prior step's `result` (classic working-memory data) referenced inline as `$story_idea` → `Successfully validated bundle`. Both halves of the doc's dichotomy fail. — adversarial verify: **CONFIRMED** (verifier judged misleading-or-wrong both defensible; graded **wrong** here because the rubric reserves *misleading* for statements that are technically defensible, and this one is not).
- *Why the wave missed it:* the reviewer **did** check the adjacent bullet — the `@@`/`$$` escaping prose, which is mechanically checkable against the preprocessor and correct — and moved on. The false bullet sits directly above it, and refuting it requires holding *two* code facts together (what `@` compiles to, **and** what `declared_inputs` contains) rather than looking one fact up. ## Dogfood observations (for the drift-contracts Phase 3 verdict, per D5)

**The headline finding of Part 4 is not a page — it is a correlation.** Every page in this part written by the tooling's *own maintainers, for themselves* came back clean: `drift-contracts.md`, `keyword-only-arguments.md`, `setup/telemetry.md`, `mthds-language-tutorial.md`. Every page that describes tooling **to someone else** — the onboarding page, the contributor setup, the agent playbook, the docs-site notes for agents — drifted. The drift is not where the code is complex; it is where **the author is not the reader**. That is an argument for drift contracts precisely on the *reader-facing* pages, and against spending contract budget on the maintainer-facing ones (which stay current by use).

- **New drift-contract candidate: `doc-make-targets-vs-makefile`.** Part 4's distinctive class. Note the shape carefully: **the failure is not a phantom target** (a target-existence check would have caught *zero* of these findings — every documented target exists). It is a **target whose behavior changed under a stable name** (F8: `agent-test` grew a heartbeat, silently invalidating a page built on its silence). A useful check must diff the *described behavior* against the recipe, which is not mechanizable — so the honest conclusion is that this class wants a **drift contract** (trigger: `Makefile` → review target: the pages that describe `make` targets), not a derived check. This is the strongest evidence yet for a contract rather than a script.
- **`doc-enumerations-vs-registry` gets a third data point** (F10, and F4's mkdocs-plugin list — a *config-file* enumeration, widening the candidate beyond code registries to `mkdocs.yml`/`pyproject.toml`).
- **Two findings were only reachable by *executing*, not reading** (F1/F2 needed a real `pipelex init config` under a sandboxed `HOME`; F7 needed the literal `uv pip install --extra dev` to be run). No static check — and no amount of code-reading — surfaces these. It is a standing argument for the campaign's "run it, don't guess" rule (the same rule that saved `pipelex validate --all` from a wrong fix at Stage 0).
- **`license.md`'s `--8<--` include is the structural fix, not a lucky one.** Where a doc *includes* the source of truth instead of copying it, drift becomes impossible rather than merely absent. Worth generalizing where feasible.
- **Docs edited in the same commit as their code do not drift** — the two contribute pages prove it (`d3550330a`, `15e0a94ea`), and it is precisely the behavior a drift contract is designed to *force* on pages whose authors would otherwise not think to touch them. The campaign now has direct evidence for the mechanism, not just for the problem.
- **⚠ The limit of a validator-based check, discovered the hard way (F13).** The tutorial's four bundle examples all pass `pipelex validate bundle` *and* a dry run — and the page still teaches a false rule, in the prose *explaining* those examples. The candidate `validate-doc-bundle-examples` check would have returned green on this page. **A snippet checker verifies the snippet, never the sentence next to it.** Worse, the wave's own reviewer verified the mechanically-checkable bullet (`@@`/`$$` escaping — correct) and skipped the false bullet directly above it, because refuting that one required holding *two* code facts together (what `@` compiles to **and** what `declared_inputs` contains) instead of looking one fact up. Derived checks buy less coverage on teaching pages than the Part-1 evidence suggested; the residue is exactly the conceptual prose, and only a human or an adversarial reader catches it.
- **One code defect surfaced and deferred** (D8): `GatewayTelemetryManagerInjectedError`'s remediation message names five telemetry config fields that do not exist. Recorded in `deferred-code-findings.md` (#3) — the mirror image of doc drift, and unreachable by any docs fix.
