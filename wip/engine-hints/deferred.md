# Engine intent hints (H2) — deferred items

Items identified during H2 execution that are deliberately not done in this branch. Each is small and self-contained; none blocks the milestone.

- **Hint lint on the CLI and builder validate channels.** `build_current_library_hint_warnings()` is wired only into `pipelex/pipeline/validate_in_process.py` (the report/API path). The bare CLI (`pipelex/cli/commands/validate/_validate_core.py`), the agent CLI (`pipelex/cli/agent_cli/commands/validate/_validate_core.py`, three sites), and the builder ops (`pipelex/builder/operations/validate_ops.py`, three sites) each assemble their `warnings` from `build_optionality_warnings` alone, so an author validating through those channels does not see the hint lint. All seven sites run inside the validation library window, so appending `+ build_current_library_hint_warnings()` is mechanical — but it touches three presentation surfaces whose output shape each needs verifying, so it was deferred rather than folded into Phase 3. Consider a shared "all advisory warnings" composition point when doing it, instead of an eighth copy of the pattern.

- **Builder emission of hints (spec layer + writer).** `pipelex/builder/operations/concept_ops.py`'s writer emits from `ConceptSpec` / `ConceptStructureSpec`, and neither spec model has a `hints` field — the builder spec layer stays `dict[str, str]`-input hint-free by design this milestone (all `*_spec.from_blueprint` sites read `inputs_concept_specs`). Preserving hints on a builder rewrite is therefore not a writer one-liner: it needs the two spec models to grow the field, the `from_blueprint` conversions to carry it, and the writer to emit it. It sits beside the known E8 spelling bug in the same writer; do them together.

## Class-backed `HtmlContent` sites: deriver honors, lint says OTHER

`_node_site_kind` (input_form.py) excludes Html-backed nodes from text-valued by looking for `native.Html` in the node's `concept_ref`/`refines` — which a `structure = "HtmlContent"` class-backed concept never carries, so the deriver treats it as text-valued and honors a `prose`/`label` hint there, while the lint (spec-faithful: Html is not text-valued) classifies the same site OTHER and warns. Fixing the deriver needs the node to carry the backing-class fact (or the deriver to thread it through), which touches the wire `refines` semantics — out of proportion for an exotic authoring (`structure = "HtmlContent"` with an intent hint). Revisit if the descriptor ever grows a backing-class member. Surfaced by PR #1148 review triage (2026-08-23).
