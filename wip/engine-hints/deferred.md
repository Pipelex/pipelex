# Engine intent hints (H2) — deferred items

Items identified during H2 execution that are deliberately not done in this branch. Each is small and self-contained; none blocks the milestone.

- **Hint lint on the CLI and builder validate channels.** `build_current_library_hint_warnings()` is wired only into `pipelex/pipeline/validate_in_process.py` (the report/API path). The bare CLI (`pipelex/cli/commands/validate/_validate_core.py`), the agent CLI (`pipelex/cli/agent_cli/commands/validate/_validate_core.py`, three sites), and the builder ops (`pipelex/builder/operations/validate_ops.py`, three sites) each assemble their `warnings` from `build_optionality_warnings` alone, so an author validating through those channels does not see the hint lint. All seven sites run inside the validation library window, so appending `+ build_current_library_hint_warnings()` is mechanical — but it touches three presentation surfaces whose output shape each needs verifying, so it was deferred rather than folded into Phase 3. Consider a shared "all advisory warnings" composition point when doing it, instead of an eighth copy of the pattern.

- **Builder emission of hints (spec layer + writer).** `pipelex/builder/operations/concept_ops.py`'s writer emits from `ConceptSpec` / `ConceptStructureSpec`, and neither spec model has a `hints` field — the builder spec layer stays `dict[str, str]`-input hint-free by design this milestone (all `*_spec.from_blueprint` sites read `inputs_concept_specs`). Preserving hints on a builder rewrite is therefore not a writer one-liner: it needs the two spec models to grow the field, the `from_blueprint` conversions to carry it, and the writer to emit it. It sits beside the known E8 spelling bug in the same writer; do them together.

## Lint/deriver site-kind divergences: deriver honors, lint says OTHER

The lint classifies sites over the qualified crate (`_resolve_concept_kind`) while the deriver re-derives applicability from node facts (`_node_site_kind`), and the two judgments are known to diverge in two spots — in both, the lint warns `hint_inapplicable_intent` while the deriver honors the same hint on the wire:

- **Class-backed `HtmlContent`.** `_node_site_kind` (input_form.py) excludes Html-backed nodes from text-valued by looking for `native.Html` in the node's `concept_ref`/`refines` — which a `structure = "HtmlContent"` class-backed concept never carries, so the deriver treats it as text-valued, while the lint (spec-faithful: Html is not text-valued) classifies the same site OTHER and warns. Surfaced by PR #1148 review triage (2026-08-23).
- **Unresolvable-base chains.** A concept refining a base the crate cannot resolve (cross-package or dangling ref) is OTHER to the lint ("not classifiable in-crate") but prose-promoted by the deriver, whose PROSE node `_node_site_kind` calls text-valued — so an `intent = "label"` there both warns AND flips the kind. Surfaced by the pre-landing adversarial review (2026-08-23); which side is right is a spec judgment (is a prose-promoted unresolvable site text-valued?).

The shared root cause is the re-derivation: `_node_site_kind` reconstructs the site kind from node facts instead of receiving the crate-walk judgment. The clean fix threads the site kind from the crate walk into `_with_effective_hints` (or gives the node a backing-class fact), which touches the wire `refines` semantics — out of proportion for these exotic authorings. Revisit together, as one shared-classifier fix, if either case shows up in real methods.

## Review deferrals (pre-landing review, 2026-08-23)

Decision-first or marginal items from PR #1148's pre-landing review — none is a defect in the shipped behavior; each needs a ruling or is a cleanup not worth widening the diff for:

- **`sync-controller-inputs` quick-fix drops authored slot hints.** `pipelex/pipeline/fixes/planner.py` (`SetKeyOp` sites) rewrites a slot to the plain `expected_ref` string, so applying the fix to an expanded slot `x = { concept = "…", hints = { … } }` silently discards the hints. Decide: preserve hints through the rewrite, or document that sync replaces the slot wholesale.
- **Pipe-declaration merge drops the losing declaration's slot hints.** `contracts_match` deliberately compares the concept-spec projection (hints are non-normative), so in `library_crate_factory` a hinted signature merged with a hint-free concrete definition keeps the definition's slots — the signature's hints vanish with no diagnostic (two matching signatures tie-break deterministically but arbitrarily). Definition-is-authority is defensible; decide and document.
- **Hint content is echoed raw and unbounded into warning messages.** The lint interpolates authored hint keys/words verbatim into `ValidationErrorItem.message` (one item per unknown key), consistent with how descriptions already flow — but a hostile bundle can inflate message size and warning count. Consider eliding long tokens and capping per-site findings when wiring the lint into the CLI/builder channels (first bullet above).
- **`qualify_crate` runs twice per validate pass.** `build_input_form` and `build_current_library_hint_warnings` each qualify the same accumulated crate inside one `validate_bundles_in_process` window — a duplicated whole-crate model_copy walk. Share the `QualifiedCrateContent` (e.g. qualify once in `validate_in_process` and pass it to both; `build_hint_warnings(qualified)` already takes one).
- **Class-name → `NativeConceptCode` reverse lookup exists in three places.** `hint_warnings._native_class_value_kind`, `input_form._class_backed_node`, and `NativeConceptCode.get_native_structure_class` each scan the enum by `structure_class_name`; a `NativeConceptCode.from_structure_class_name(...)` classmethod would replace the comment-enforced mirroring with shared code.
- **Hints dicts are aliased across copies.** `_qualify_slot_value`'s `model_copy` shares the `hints` dict between raw and qualified crates, and list/item nodes share one merged dict. No current code mutates a hints dict in place; if a mutator ever appears, copy at the stamp sites.
