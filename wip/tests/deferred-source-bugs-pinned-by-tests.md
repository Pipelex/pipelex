# Source bugs pinned by the coverage-grind tests — RESOLVED (cleanups remaining)

Outcome of the post-grind code review (2026-06-12, branch `feature/Add-tests`). The coverage grind (TODOS.md Phases C/D/E) deliberately wrote tests that pin **current** behavior — including behavior the review then judged to be wrong at the source. The defects were initially deferred here; they have since been **verified and fixed on this same branch** (2026-06-12), with each pinning test flipped alongside its source fix and the fixes recorded in `CHANGELOG.md` under `[Unreleased]`.

Applied fixes (see CHANGELOG for user-facing wording):

1. **OpenAI image moderation mapping inverted** — `moderation_for_openai_image` now maps enabled → `"auto"`, disabled → `"low"`; the OPENAI_MODERATION parametrize rows flipped with it.
2. **GCP storage `lazy_validate` accepted uri_format without a real `{hash}` placeholder** — now checks the literal `"{hash}"` like S3, and the GCP error message gained the `- ` fix-line prefixes and docs URL; the bare-substring acceptance test became a rejection parametrize row. A post-fix review pass then extended this: the per-provider checks and message assembly were consolidated onto a shared `StorageMethodConfig` base (S3/GCP can no longer drift apart), and the local/in-memory configs — which had NO validation at all and were exposed to the same constant-URI overwrite — got `lazy_validate` too, wired into the storage provider factory like S3/GCP and pinned by their own test modules.
3. **Bundle-spec string-concept arm mapped the string into `structure`** — the string now passes through to the blueprint dict, where the loader treats it as the concept's description.
4. **`ConceptSpec.model_validate_spec` crashed on non-dict input** — gained the same `isinstance(values, dict)` guard as `ConceptBlueprint.validate_mutually_exclusive_fields`, so the `ConceptSpec | str` union falls through to `str` normally. All `model_construct` workaround sites in the bundle-spec tests were swept back to normal construction, and a test pins the normal-validation path for string concepts.
5. **Mistral `make_simple_messages` sent the system message AFTER the user message** — system now comes first, matching the docstring and the OpenAI-typed sibling; the ordering test flipped.
6. **`StorageProviderConfig.storage_path` ignored `method` and raised a misleading message** — the property now dispatches on method (mirroring `uri_format`), raising "storage_path is only available when method is local" for non-local methods; both pinning tests flipped.
7. **LocalObserver let a payload's own `event_type` overwrite the event name** — merge order flipped so the lifecycle event name wins; the pinning test flipped with it.

## Deferred design tradeoffs (from the post-fix review pass)

- **LocalObserver flat record namespace:** the merge-order fix guarantees the lifecycle `event_type` wins, but lifecycle metadata and arbitrary payload keys still share one flat dict in the JSONL record. Any future metadata field (timestamp, run id) re-opens the same collision class with whatever payload key shares its name. The deeper fix is nesting the payload under its own key (e.g. `{"event_type": ..., "payload": {...}}`), which is a breaking change to the JSONL record shape for downstream consumers — decide deliberately, don't slip it into an unrelated change.

## Test-quality cleanups (no source impact, batch when convenient) — STILL DEFERRED

- **Pipelex-boot opt-out for pure test dirs:** many of the new pure-logic modules (tools/misc, tools/storage, plugins factories, model_deck_check, backend_credentials) pay the autouse module-scoped `Pipelex.make()` from `tests/conftest.py` without using it. Precedent exists: `tests/unit/pipelex/system/pipelex_service/conftest.py` overrides `reset_pipelex_config_fixture` with a no-op. A one-file conftest per pure directory shaves seconds off every suite run.
- **Hoist duplicated scaffolds where a shared home already exists:** the three `graph/test_graph_rendering_*.py` files rebuild the same bundle-write + `dry_run_pipeline` AsyncMock scaffold (and `graph/conftest.py` already exports shared helpers); `make_llm_spec` is copied across the three `builder/test_bundle_spec_*.py` files (builder subpackages use `test_data.py` modules for exactly this); the storage trio re-implements the S3/GCP config builders in `test_storage_provider_config.py`.
- **Minor in-file dedup:** `test_storage_provider_config.py` carries the same 4-row method table twice; `test_local_observer.py`'s str/Path constructor twins could be one parametrized test; `test_model_deck_check.py` rebuilds the full ModelDeck inside every parametrized case (class-scoped fixture would do); `NESTED_TOML_CONTENT` is duplicated across two toml_sync files; `test_inputs_ops.py`'s fixture dict carries an unused `get_library_manager` key; the mistral messages tests use id()-keyed side_effect closures with asserts inside mocks where positional `side_effect=[...]` + post-hoc assertions would fail more readably. (Done already: `test_storage_s3_config.py`'s standalone braced-hash test that duplicated a parametrize row was removed during the fix pass.)
