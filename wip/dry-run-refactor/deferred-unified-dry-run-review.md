# Deferred items — unified dry run review rounds (PR #986)

> Findings from the PR #986 review rounds (greptile/cubic bots + the `/review` specialist/adversarial passes, 2026-06-10) that were **verified real but deliberately NOT fixed** — each is a design tradeoff or a guard for a currently-unreachable path, not a silent bug in shipped behavior. Fixed-on-the-spot findings are not listed (see the PR's commits).

## Run-mode safety & contracts

- **Typed-error wrap of the `cogt_run_params` mint + factory contract check.** The derived property and `PipeRunParamsFactory` raise pydantic `ValidationError` / `ValueError` on the LIVE+`is_mock_usage` violation. Inside Temporal *workflow* code an unconverted exception retries forever (the known submitter-hang class) — but post-hardening the illegal state requires deliberately bypassing validators (`model_copy(update=...)` on exactly those fields; attribute writes are blocked by `Field(frozen=True)`). Guarding that is guarding a near-impossible path; revisit only if a real producer of the illegal state appears. Same family: the factory's `ValueError` surfacing as an untyped 500 through `pipelex-api` once that repo adopts `is_mock_usage` — decide a typed INPUT-domain error at that adoption point, not before.
- **Keyless-boot trust boundary narrowed (D4 consequence).** Pre-Part-B, a keyless boot installed a mock generator globally, so even direct `ContentGeneratorProtocol` callers got mocks. Now generator selection is backend-keyed only and forced-DRY lives at `make_run_params` — an embedder calling the protocol directly with a hand-built LIVE carrier under a keyless boot whose lenient backend load found credentials *can* reach a real provider. This is the submitter-side-contract-only design decided in eng review D4; flagging the contract change here for visibility. A `is_dry_run_forced()` guard at `get_content_generator()` would restore the old blanket but re-couples generator selection to run mode — rejected for now.
- **Forced-DRY silently downgrades an explicit LIVE request (warning only).** A misconfigured production boot (keyless by accident) returns synthetic structured outputs to clients with only a server-side `log.warning`. Options: fail loud when the LIVE request was *explicit* (coerce only defaulted modes), or stamp `run_mode` into client-visible output metadata. Interacts with the already-deferred `PIPELEX_FORCE_DRY_RUN_MODE` env-var cleanup (see `wip/dry-run-refactor/README.md` open table) — decide together.
- **`hub` forced-DRY flag is process-global, not ContextVar-scoped.** Consistent with the other hub singletons, but it guards spend; if embedded re-boot-while-running ever becomes a supported pattern, move it to the ContextVar style of `scoped_content_generator`.

## Dry-leaf behavior

- **`stamp_mock_main_coordination` can corrupt a user item class that happens to have a constrained `pipe_code` field** (direct attribute write, no validation), and the resulting `DryRunObjectFidelityError` remedy ("declare `examples`/`mock_format`") cannot fix a framework-injected value. Niche (requires a user output class with a constrained `pipe_code`), and the stamp is load-bearing for bundle dry-validation (D3). Candidate fix: pin the field through `build_mock_object(pipe_code="mock_main")` for the first item (runs validators) or scope the stamp to the builder's spec classes.
- **Ambient `dry_run_config.nb_extract_pages` read at two leaves** (extract + render-page-views) — under Temporal these run in different activities; heterogeneous worker configs would mismatch counts and trip the generator's length check. Already tracked since the B1 review round (`followup-leaf-run-mode-mock.md`); the D11-style fix (carry the resolved count on the assignments) stands. Note: the "both `image_uri` and `document_uri`" variant of this finding is impossible — `ExtractInput` validates exactly-one.
- **Inline page-view count mismatch raises bare `ValueError`; the in-workflow twin raises `ContentGenerationError`.** Cross-backend error-type inconsistency on the same fault (pre-existing). Aligning changes error classification on a live path (`ValueError` is in `non_retryable_error_types`); do it together with the nb_extract_pages fix above.
- **Dry image mocks hardcode `mime_type="image/jpeg"` + 1024×1024** while `dry_run_config.image_urls` includes a `.png` — mock metadata can contradict the URL it points at (pre-existing, carried from `ContentGeneratorDry`). Derive mime from the URL suffix if a consumer ever keys on it.

## Reporting & surfaces

- **Synthetic usage is discriminated only by sentinel model-name strings** (`dry_run` / `mock_usage`, `unit_costs={}`). Cost stays $0 by construction, but a downstream aggregator summing `nb_tokens_by_category` without filtering the sentinels would mix synthetic tokens into real usage metrics. A structural `is_synthetic` marker on the usage record is the durable fix — wire-format change, do it when a real aggregator consumer appears (Temporal not in prod).
- **Validation sweeps now reach the `exec()` codegen path.** `BundleValidator` / `dry_run_pipe_in_process` swapped `ContentGeneratorDry` (original-class mocks, no codegen) for the inline `ContentGenerator`, whose dry object leaves run schema-reconstruction (datamodel-code-generator → `exec()`). The hosted `/validate` surface — keyless, typically less gated than execution — now exercises the codegen pipeline on user-bundle-derived schemas. The factory's own docs say its containment is defense-in-depth, not a sandbox; its existing hardening TODO (programmatic `create_model()` or subprocess sandbox) gains priority from this surface expansion.
