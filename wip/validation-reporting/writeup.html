Validation-error reporting — quality track

Make every Pipelex validation error read like a fix, not a stack trace — on every surface. · feature/Autofix · 2026-07-09

Phases 0–4 done make agent-check ✓ full agent-test ✓ one engine → every surface conformance regen — release-gated

TL;DR

Validation errors used to leak Python internals (multiplicity=None, Concept(...) reprs, Value errors: '<field>': Value error,) and the actionable content lived only in the 💡 Suggested fix line — which the agent surface didn't even render. We fixed the messages at the engine so every surface benefits at once.

  • Messages now speak MTHDS author syntax. "declares its output as 'StoryIdea', but its last step yields 'StoryIdea[]'. Update the sequence's output to 'StoryIdea[]'" — states the problem and the exact edit.
  • The agent CLI renders prose, not a raw JSON dump: grouped items, humanized titles, per-error 💡 Suggested fix lines, and a footer naming the exact pipelex-agent fix bundle command.
  • The top-line message is a clean summary everywhere — agent JSON and the API /validate body — instead of a pydantic dump. The API's opt-in rendered_markdown gained the same 💡 prose.
  • One engine, zero drift. Human CLI, agent markdown/JSON, and the API all draw from the same raise-site messages + shared ValidationErrorItem builder. The machine JSON contract is byte-stable — only presentation improved.
  • Status: all code is uncommitted on feature/Autofix, gates green. One follow-up (the conformance/validate-error-qa corpus regen) is release-gated because it freshness-tests the live API.

Why we did this

The autofix track (steps 1–5) shipped deterministic bundle fixes and a 💡 Suggested fix line. Dogfooding a playground of deliberately-broken bundles (pipelex-demos/bad_bundles/) surfaced a quality gap: the three surfaces were consistent (good — one engine), but the core error message was carrying almost none of the weight. It leaked internal repr, and the agent surface dumped raw JSON. We diagnosed six recurring "diseases":

#DiseaseFixed in
AInternal Python repr in the message (multiplicity=None, Concept(...), PresenceMarker)Phase 1done
BMisleading (required: [...], provided: ...) suffix — list-repr brackets mimic MTHDS [] syntaxPhase 1done
CPydantic top-line leak in agent JSON + API message (Validation error(s): … Value errors: …)Phase 3done
DAgent validate markdown = raw JSON dump, not prosePhase 2done
EBoilerplate agent hint ("Check the validation_errors array…") with no actionPhase 2done
F"Must be in snake_case" slightly misleads on dotted codes—deferred

Disease F was deliberately deferred: low value (the 💡 line already says "Strip the same-domain prefix") and it would churn a well-pinned categorizer contract.

Mental model — one engine, every surface

The whole design rests on a single principle from the workspace's "format follows consumer" doctrine: improvements go into the message at the raise site or the shared item builder / renderer — never into per-surface private wording that can drift. Everything downstream is presentation.

Phase 3 · disease C — clean the top-line at the source

The leak lived in ValidateBundleError.message, built by str()-ing a pydantic ValidationError. Rather than patch it per-surface (which would drift CLI vs API), we summarize from the already-clean structured items in the constructor — so agent JSON and the API report both benefit.

pipelex/pipeline/exceptions.py — new summarizer, called from ValidateBundleError.__init__
+def _summarize_bundle_validation_message(*, blueprint_errors, factory_errors,
+        pipe_validation_errors, dry_run_error_message, raw_message) -> str:
+    item_messages  = [e.message for e in blueprint_errors]
+    item_messages += [e.message for e in factory_errors]
+    item_messages += [e.message for e in pipe_validation_errors]
+    if not item_messages and dry_run_error_message:
+        item_messages = [dry_run_error_message]
+    # No categorized data → a parse-level failure (TOML syntax); raw message is authoritative.
+    if not item_messages:
+        return raw_message
+    if len(item_messages) == 1:
+        return item_messages[0]
+    return f"{len(item_messages)} validation errors (first: {item_messages[0]})"

     def __init__(self, message, ...):
         ...  # store the categorized error-data lists
-        super().__init__(message)
+        super().__init__(_summarize_bundle_validation_message(
+            blueprint_errors=self.pipelex_bundle_blueprint_validation_errors,

The fallback keeps the pipelex-api pin "TOML" in body["message"] green: a TOML-syntax failure has no categorized items, so the raw message (which names "TOML") passes through unchanged.

Design decisions worth knowing

No new wire fields

We considered adding expected_output_ref to ValidationErrorItem. Declined: the suggested_fix ops already carry the machine-actionable data (set_key output = "StoryIdea[]") and the message states it in author syntax. Adding it would expand the contract (changelog + conformance regen) for no concrete consumer — against "smallest correct surface".

Category framing subsumed

The old "Could not load blueprints/concepts because of:" prefix rode the leaky pydantic message. It's now dropped from message (the structured items carry the category), so test_validate_bundle_category_framing.py was retargeted from a framing pin to a clean-summary invariant.

JSON contract byte-stable

Only the top-line message (presentation) changed in JSON; validation_errors[], is_valid, hint, and the envelope shape are untouched. PostToolUse hooks that pin --format json keep working unchanged.

Human surface unchanged

The human CLI already rendered items (not exc.message), so it was byte-identical through Phases 3–4. The full-sweep re-capture confirmed the only per-scenario delta vs Phase 2 is the JSON message line.
