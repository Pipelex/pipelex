# Structured logs: findings deferred by review passes

Traces for what a review pass on a structured-logs member read as real but not worth fixing at that pass's bar. ## L-260916-a1dbd5, round 1 (fields, context, no stack walk)

- **Caller attribution rides a fixed frame depth** (*unverified*, cubic). `CALLER_FRAME_DEPTH` in `pipelex/tools/log/log_dispatch.py` counts the frames between the frame lookup and the code that called `log.<level>(...)`, so a helper inserted into or removed from that call chain would attribute records to the wrong module and apply the wrong logger level. The tests in `tests/unit/pipelex/tools/test_log_caller_module.py` emit through every level and assert the caller's module, path and function, which is what catches such a change. A walk up the frames until one leaves the log package would remove the constant at the cost of a loop per line; the fixed depth stays until a second facade entry point makes the constant wrong for one of them.
- **A given `field_<name>` beside a colliding `<name>`** (*unverified*, cubic). Prefixing a colliding entry could overwrite an entry the caller gave under the prefixed name. Deferred here on the reading that the ordered attach kept both values; round 2 verified that it did so in one order only, and fixed it: the prefix is now applied until the destination is free.
- **The traceback rides the message rather than `exc_info`** (verified by inspection, code-review and the implementer). `include_exception` appends `traceback.format_exc()` to the message text in the dispatch. A structured sink wants the exception as `exc_info` or `exc_text`; setting it today would make the Rich handler render the traceback twice. The sink member L-260916-aa6e58 owns that decision, and the note on it carries the detail.

## L-260916-a1dbd5, round 2 (bar defects)

- **`is_console_logging_enabled = false` silences every handler, not the console** (*unverified*, code-review). The early return in `LogDispatch.dispatch` precedes `logger.handle(record)`, so a deployment that turns the console off to attach its own handler to the root logger gets no Pipelex record at all. The gate is the one the old console-only dispatch had, and it is the sink member's to replace: L-260916-aa6e58 selects sinks by configuration and retires the rich-or-poor mode, and the note on it carries this.
- **The formatter mutates `record.msg` in place** (*unverified*, code-review, outside the diff). `LevelAndEmojiLogFormatter.format` in `pipelex/tools/log/log_formatter.py` rewrites the record's message for WARNING and above, so a record formatted by more than one handler accumulates colour escapes. Pre-existing; it starts to matter when a second handler exists, which is the sink member's work, and the note on L-260916-aa6e58 carries it.
- **A `data` field is overwritten by structured content rather than prefixed** (*unverified*, code-review). `build_log_record_extra` lets the content's `data` win over `fields={"data": ...}` outright, the one place a value is discarded rather than carried under a prefix. Documented as deliberate in `docs/tools/logging.md`; no call site gives such a field, and a rule that prefixes it would be a change of contract rather than a fix.
