Keyword-only arguments, everywhere — and a guard that keeps it that way

A codebase-wide refactor + a mechanical enforcement guard, plus the lockstep update of every downstream consumer. Written for the people who'll write the next function.

TL;DR

  • What changed: across all of pipelex/, every non-subject function parameter is now keyword-only. A function may keep its first real argument (the "subject") positional; everything after it must be passed by name. So do_thing(retries=3, timeout=30) — never the opaque do_thing(3, 30).
  • Why: call sites become self-documenting, and you can reorder / insert parameters without silently rebinding a caller's positional args.
  • How it stays true: a stdlib-only AST guard (check-keyword-only) runs in make agent-check, in the make check aggregate, and in CI — it hard-blocks on any violation. A PostToolUse hook runs the same guard on each edited file in ~40 ms, so agents get blocked in-loop, not at CI.
  • The sweep: ~1,800 functions audited (one Sonnet sub-agent per package); 59 "kept-positional-out-of-habit" suspects were found and all made fully keyword-only — by relocating the bare * only, no reordering, no renames.
  • Breaking & downstream: the public surface (Pipelex.make() / setup() / PipelexHub.setup_config()) is now keyword-only after the subject. All four consumer repos (pipelex-api, cocode, cookbook, starter-python) were re-pinned to the branch and fixed in lockstep — exactly one real call-site break across all of them. Green on agent-check + agent-test; PRs pushed.
  • One open item: at pipelex release, swap each consumer's temporary git pin back to a released version.

The rule, in one picture

The compliant shape places a bare * right after the subject. The subject — the first non-self/cls parameter — may stay positional; making it keyword-only too is always allowed and often nicer.

def render(node): ...                       # lone subject — fine
def f(subject, *, opt1, opt2): ...          # subject positional, rest keyword
def f(*, a, b): ...                         # fully keyword-only — always allowed
def make(cls, *, integration_mode=...): ... # classmethod, fully keyword-only
def f(a, b): ...                            # second bare positional
def truncate(text, max_length=80): ...      # max_length must be keyword-only
def make(cls, integration_mode, *, ...): .. # subject kept positional "by habit"
                                            #   when every call site already
                                            #   passes integration_mode=...
# A genuinely justified one-off — placed right after the open paren so
# `ruff format` keeps it on the def header line:
def legacy_cb(a, b):  # kw-only: ignore
    ...

# Carve-outs are automatic (no marker needed): dunders, pydantic
# validators/serializers, Typer/Temporal/pytest/Jinja2 entrypoints,
# @override impls, and a curated symmetric-tuple allowlist.

How it stays true: three layers of enforcement

One rule, one AST core, three places it fires. The guard is stdlib-only (ast/re/pathlib) so the single-file path can run without importing the pipelex package chain — that's what keeps the editor hook at a few tens of milliseconds.

The carve-outs (skipped automatically) and the escape hatch
  • Dunders — __init__, __call__, … (interpreter calls them positionally).
  • pydantic — @field_validator, @model_validator, @field_serializer, @model_serializer, @validator, @root_validator.
  • Framework entrypoints invoked positionally — Typer @app.command/@app.callback (and the decorator-less Argument(...)/Option(...) annotation form), Temporal @activity.defn / @workflow.run|signal|query|update, @pytest.fixture, and Jinja2 @pass_context/@pass_environment/@pass_eval_context.
  • @override impls — they track the base signature.
  • Curated symmetric-tuple allowlist — a handful of (qualified_name, path) pairs where both operands are genuinely peers (e.g. diff_files(a, b)). No pattern guessing; both name and path must match exactly.
  • Escape hatch — an inline # kw-only: ignore on the def line, for a justified one-off.

The type checker can't see framework-positional callbacks (route handlers, __import__ hooks), so make agent-test is the safety net — and it caught real cases during the rollout.

Rolling it out: audit → consolidation → enforce

The tree was made compliant wave by wave (execution path, then the framework-sensitive & public API last). Then a dedicated pass hunted the subtler problem: signatures that satisfied the rule on a technicality — they kept a subject positional — but where that "subject" was really a lookup table, a mode flag, or a trace-context carrier, while the actual operand sat in the keyword args.

The recurring shapes the 59 suspects collapsed into
  • Lookup-table / registry carried positional while the real query is keyworded — e.g. model_cost_per_token(costs, *, cost_category), get_reasoning_level_str(effort_to_level_map, *, effort).
  • *_for_pipe / *_from_response / *_from_uri — the name advertises the operand, but a different arg was positional.
  • Mode flag / bare bool positional — f(True) reveals nothing, and every call site already keyworded it.
  • Trace/provenance carrier positional (job_metadata, lookup_key, calling_pipe_code) while the function acts on the keyword args.
  • Accumulator/sink dict positional while the content being added is keyworded.
  • Symmetric pair split across the * — neither operand is "the subject", so the split was just noise.
  • Public-API surface — Pipelex.make/setup, a deliberate keyword-only break.

A near-universal tell: the existing call sites already passed the "positional" arg by keyword — the positional permission was buying nothing.

Downstream: one branch SHA, five consumers, exactly one real break

pipelex/cli/dev_cli/commands/keyword_only_guard.py (new · stdlib-only) — the rule
def _positional_or_keyword_count(node, *, is_method: bool) -> int:
    """Count positional-or-keyword params after dropping self/cls and the allowed subject."""
    params = [*node.args.posonlyargs, *node.args.args]
    if is_method and params and params[0].arg in {"self", "cls"}:
        params = params[1:]
    params = params[1:]            # drop the single allowed subject (Exception 1)
    return len(params)             # *args/**kwargs and kw-only params are not counted

def _evaluate_def(node, *, module_qname, relative_path, class_stack,
                  func_stack, is_method, source_lines) -> Violation | None:
    # carve-outs first — any match => skip entirely
    if _is_dunder(node.name): return None
    if _def_line_has_escape_hatch(node, source_lines=source_lines): return None
    if _has_carveout_decorator(node): return None       # pydantic / Typer / Temporal / pytest / Jinja2 / @override
    if _has_typer_param_annotation(node): return None   # decorator-less Typer entrypoints
    if (dotted_qname, relative_path) in SYMMETRIC_ALLOWLIST: return None

    # the rule: a bare * is required once any non-subject positional-or-keyword param remains
    if _positional_or_keyword_count(node, is_method=is_method) >= 1:
        return Violation(relative_path=relative_path, qualified_name=local_qname, lineno=node.lineno)
    return None

A _Collector(ast.NodeVisitor) walks the module tracking the class/function scope; find_violations_in_source() is the shared core both entrypoints call. A mid-edit SyntaxError is skipped, never reported — the hook must not block on a transient parse error.

.claude/hooks/check-keyword-only.sh (new) — the in-loop gate
# PostToolUse hook: run the stdlib-only AST guard on the just-edited file (~40ms).
PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$PWD}"
GUARD="$PROJECT_DIR/pipelex/cli/dev_cli/commands/keyword_only_guard.py"
PYTHON="$PROJECT_DIR/.venv/bin/python"

input=$(cat)                       # tool-call JSON on stdin (pure bash, no jq — house style)
file_path=$(echo "$input" | grep -o '"file_path"[[:space:]]*:[[:space:]]*"[^"]*"' \
  | head -1 | sed 's/.*"file_path"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/' || true)

[ -z "$file_path" ] && exit 0      # fast, silent pass-through ...
case "$file_path" in *.py) ;; *) exit 0 ;; esac   # ... non-.py rejected in bash, no Python launch
[ -x "$PYTHON" ] || exit 0
[ -f "$GUARD" ] || exit 0

cd "$PROJECT_DIR"                   # invoked by FILE PATH (not -m) → skips the pipelex import chain
exec "$PYTHON" "$GUARD" "$file_path"   # exit 2 + stderr → Claude Code surfaces it as blocking feedback

Running by file path instead of python -m is deliberate: -m would import pipelex/__init__.py → rich and blow the cold-start budget.
