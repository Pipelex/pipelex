TL;DR

  • This branch is a unit-test grind over the offline-testable layers of pipelex (CLI internals, Temporal entry points, inference plumbing, core runtime, tools/config). The diff is almost entirely new tests.
  • Writing those tests surfaced a small, deliberate set of real source bugs. Each was pinned by a test first, judged wrong in review, then fixed with the test flipped. That's the only behavior change in the PR.
  • The headline fix is storage uri_format validation: a misconfigured format string used to silently render the same URI for every object (storage-wide overwrites). It now fails fast at boot with an operator-facing message — and the rule is enforced uniformly on every placeholder.
  • One load-bearing infra fix: pytest's default norecursedirs includes build, so an entire tests/.../build/ tree (including a pre-existing regression test) was never being collected. Now fixed in pyproject.toml.
  • How to review: read the source changes below (they're the only behavior diff), then sample the tests with the conventions section in mind. Remaining uncovered lines are deliberate (interface layer is owned by the conformance repo).

2 · The source bugs (the behavior diff)

Each tab is one fix. They are independent. Minimal diffs only — the surrounding code and tests are in the branch.

Storage uri_format validation — the biggest fix

The bug. GCP's lazy_validate accepted any format string containing the bare substring hash (e.g. assets/myhash/file) — no substitution slot, so every stored object renders the same URI: silent storage-wide overwrites. Local and in-memory configs had no validation at all. The check now parses the format string and requires a real, plain {hash} replacement field.

The per-provider checks moved onto a shared StorageMethodConfig base so the providers can't drift apart:

classDiagram ConfigModel <|-- StorageMethodConfig StorageMethodConfig <|-- StorageLocalConfig StorageMethodConfig <|-- StorageInMemoryConfig StorageMethodConfig <|-- StorageBucketConfig StorageBucketConfig <|-- StorageS3Config StorageBucketConfig <|-- StorageGcpConfig class StorageMethodConfig { +uri_format str +URI_FORMAT_SUPPORTED_FIELDS +lazy_validate() +_collect_uri_format_error_msgs() } class StorageBucketConfig { +bucket_name str +signed_urls_lifespan_seconds }

Validation happens at boot, when the provider is constructed. The flow for one placeholder:

supported set?"} U -- no --> UN["'{x}' is not supported"] U -- yes --> PL{"plain {name}?
no spec / conversion /
attr / index"} PL -- no --> NP["'{name}' must be plain"] PL -- yes --> H{"a {hash} present

Core of the parser (substring check → parse the format string):

pipelex/tools/storage/storage_config.py-    elif "{hash}" not in self.uri_format:           # GCP: "hash" substring only!
-        error_msgs.append("- uri_format must contain a {hash} placeholder")
+    URI_FORMAT_SUPPORTED_FIELDS = frozenset({"primary_id", "secondary_id", "hash", "extension"})
+    parsed = [(name, spec, conv) for _, name, spec, conv in
+              Formatter().parse(self.uri_format) if name is not None]
+    for name, spec, conv in parsed:
+        base = name.split(".")[0].split("[")[0]
+        if base not in URI_FORMAT_SUPPORTED_FIELDS:   unsupported.add(name)
+        elif name != base or spec or conv:            nonplain.add(name)   # see note
+        if base == "hash":                            hash_found = True
Round-2 finding (Codex adversarial pass). The first version enforced "must be plain" only on {hash}. But a format spec on any other field is just as dangerous: {primary_id:.0} truncates to "" (collisions again), and {primary_id:1000000000} would balloon the backstop's test-render into a ~1 GB allocation at boot. The elif name != base or spec or conv above generalizes the rule to every supported field, and rejects it at parse time before any format() call. Pinned by new S3 regression rows.

Also on this fix: bucket configs must set a positive signed_urls_lifespan_seconds (or "disabled") so signed URLs can't be born dead; the factory now lazy_validates local/in-memory like it already did S3/GCP; and storage_path dispatches on the configured method instead of blaming a missing local config.

OpenAI image moderation mapping was inverted

is_moderated=true sent gpt-image's less restrictive "low", and false sent "auto" — the exact opposite of "enable moderation".

         return omit

+        return "auto"    # enabled → standard filtering

pipelex/cogt/img_gen/img_gen_setting.py-    is_moderated: bool = False

The default became None so the corrected mapping doesn't silently downgrade default runs: deck alias/handle resolution builds settings without the field, and the old False default would have started sending "low". With None, workers omit the parameter and the provider's own default applies.

String concept values in bundle specs were unconstructible

Two problems: a mode="before" validator assumed dict input and crashed on the ConceptSpec | str union; and to_blueprint() shoved the string into structure, where the loader only accepts registered structure class names.

pipelex/core/concepts/concept_blueprint.py  (and concept_spec.py — same guard) @model_validator(mode="before")
- def validate(cls, values: dict[str, Any] | str) -> ...:
-     if isinstance(values, dict) and values.get("refines") and values.get("structure"):
+ def validate(cls, values: Any) -> Any:
+     # before-validators get RAW input; a non-dict (str in a union) must fall through
+     if not isinstance(values, dict):
+         return values
+     fields = cast("dict[str, Any]", values)
+     if fields.get("refines") and fields.get("structure"):
         raise ValueError(...)
pipelex/builder/bundle_spec.py- concept[code] = ConceptBlueprint(description=code, structure=string_value)
+ # a bare string is the concept's description — the blueprint layer accepts it as-is
+ concept[code] = string_value

This matches ConceptFactory.make_from_blueprint, which treats a bare string as ConceptDeclarationType.STRING (a description), not a class reference.

Output-option numbering was nondeterministic

A PipeCondition's possible outputs were collected by iterating a dependency set, so the user-facing output_option_N numbering varied between runs with two or more mapped pipes. Now sorted by pipe code.

+ for mapped_pipe_code in sorted(mapped_pipe_codes):   # stable output_option_N

(Also in this group: temporal/worker_cli.py no longer logs Starting worker for current project 'None' when no project is given.)

An entire test tree was silently never collected

pytest's default norecursedirs includes build. So everything under tests/unit/pipelex/cli/commands/build/ (mirroring the source layout) was never collected in full runs — including a pre-existing cross-package refines regression test that had never run. This is load-bearing for the whole branch: without it, a chunk of the new tests wouldn't run in CI.

pyproject.toml — [tool.pytest]+ testpaths = ["tests"]                  # bare `pytest` never scans outside tests/
+ norecursedirs = [                       # = pytest defaults MINUS "build"
+   "*.egg", ".*", "_darcs", "CVS", "dist", "node_modules", "venv", "{arch}",
+ ]
Verified empirically. pytest 9.0.3 reads the [tool.pytest] table natively (promoted to canonical in pytest 9). Recursive discovery from the repo root now finds the build/ tests (collected via recursion, not by naming the dir), and the addopts marker filter still applies. The default local config clears the new storage validation at boot.

3 · Test conventions (read before flagging)

Several patterns that look unusual are deliberate:

ConventionWhy
One TestClass per moduleHouse pytest standard — that's why e.g. doctor coverage is split across several test_doctor_*.py files.
pytest-mock (MockerFixture) onlyNever unittest.mock imports. Strong value asserts; parametrization over copy-paste.
CLI interface deliberately untestedArg parsing, --help, Typer wrappers, agent JSON shapes are owned by the sibling conformance repo. This branch tests the do_* / _core functions beneath them. Low coverage on *_cmd.py wrapper lines is by design.
Namespace vs source-module patchingTop-level imports patched at the consuming module; classes imported inside functions (deferred-import in worker factories) patched at their source module. Worker-factory tests use a fresh real PluginSdkRegistry() per test so the booted singleton is never mutated.
Real collaborators where cheapReal TOML in tmp_path, real PIL images, real pydantic SDK models, a real aiohttp server for the codec. AsyncMocks only at inference / network / Temporal SDK boundaries.
Remaining uncovered lines are deliberateTYPE_CHECKING blocks, interface-layer wrappers (conformance-owned), lines pinned by the integration suite, live-call worker paths.

4 · How it was reviewed

The behavior diff went through CI (tests py3.10–3.14, typecheck, lint, uv-lock), Greptile (multiple rounds, all threads resolved), and a local two-model adversarial pass (Claude + Codex). Findings were verified against the code, deduplicated, and only fixed when a clear win:

  • Fixed: the generalized uri_format plain-placeholder rule (Codex High — see the storage tab note).
  • Deferred (recorded in wip/tests/): a pre-existing truthiness-vs-presence edge case in the concept mutual-exclusion check, plus a handful of test-scaffold DRY cleanups. Contrived or pre-existing; not introduced here.
  • No-op: the "bare string is now a description" change is the intended fix, confirmed against the blueprint contract.

Cubic could not run this branch — the workspace hit its free monthly review-line limit (resumes July 1). External constraint, not a code issue.

Deferred items (not in this PR)
  • LocalObserver flat record namespace — the merge-order fix guarantees the event name wins, but lifecycle metadata and payload keys still share one flat dict. Nesting the payload is a breaking JSONL-shape change — decide deliberately.
  • uri_format required on configs that never consume it — the Temporal codec / in-memory paths build their own keys, yet the factory now validates a uri_format they ignore. Possible config-shape split.
  • Concept mutual-exclusion is truthiness-based — refines + empty-but-present structure slips the guard. Pre-existing; switching to is not None changes behavior for legitimately-empty structures.
  • img_gen_param_defaults partially dead config — is_moderated / safety_tolerance there are never consumed; whether they should feed setting resolution is an open design call.
  • Test-quality cleanups — a Pipelex-boot opt-out conftest for pure test dirs, hoisting duplicated scaffolds, minor in-file dedup.
