Optionals phase 1 — ? and ! land in MTHDS

Presence markers, an absence ledger with provenance, implicit lifting, and a static safety net — for co-developers reviewing PR #1021.

TL;DR

MTHDS methods can now say "this slot may hold nothing" — and both the validator and the runtime take that seriously. One PR (Pipelex/pipelex#1021 → dev) delivers the whole of phase 1:

  • Grammar: "PenaltyClause?" (optional) and "PenaltyClause!" (force) on pipe inputs/outputs, beside the existing [] multiplicity.
  • Runtime trichotomy: a pipe fed a recorded absence on a plain input is skipped (Swift-style a?.b.c chaining); a ? input absorbs (the pipe runs both arms); a ! input fails loudly with the full provenance chain.
  • Absence is data, not a crash: a ledger records why each slot is empty (who skipped, what was never provided, which continue fired), and that record survives serialization, the API wire, CLI artifacts, and graph rendering.
  • Static safety theorem: validation proves at author time that every possible absence reaches an explicit sink — no more "my workflow silently produced nothing".
  • Breaking, on purpose: PipeCondition's continue no longer passes a value through — it resolves the declared output as absent, killing the language's last invisible optional.

Status: dev is merged in, CI is green, all review-bot findings are triaged (one real P1 caught & fixed), and the PR awaits merge. Spec-suite coverage and protocol-spec sections are written but ride separate branches in the sibling repos that own them (no PRs yet — they de-gate only once both of the suite's arms run an optionals-speaking pipelex).

Why we did this

MTHDS had no way to say "no value here, and that's fine". That gap leaked everywhere:

  • Empty-string hacks. Authors returned "" or fabricated placeholder objects when an extraction found nothing — downstream pipes couldn't tell "empty" from "absent".
  • Hallucination pressure. An LLM pipe required to produce a PenaltyClause from a contract that has none will invent one. The type system was actively encouraging hallucination.
  • The invisible optional. PipeCondition's continue outcome quietly passed the previous main stuff through — a no-output path the type system couldn't see, which crashed delivery, tracing, and telemetry in creative ways.

The language: two markers, strict rules

[pipe.extract_penalty]
type = "PipeLLM"
description = "Find the penalty clause, if any"
inputs = { contract = "Contract" }
output = "PenaltyClause?"          # ← may resolve absent: no clause found is a SUCCESS

[pipe.assess_penalty]
type = "PipeLLM"
description = "Assess severity — handles both arms"
inputs = { clause = "PenaltyClause?" }   # ← absorbs: runs even when clause is absent
prompt = """
Assess the contract risk.
@?clause                            # ← guarded block: rendered only when present
"""

[pipe.compute_fine]
type = "PipeLLM"
description = "Force-unwrap: we KNOW it's there by now"
inputs = { clause = "PenaltyClause!" }   # ← asserts presence; absence = typed error

Grammar misuse is rejected at parse time with a typed error (optional_marker_invalid): markers never combine with multiplicity (X[]? is illegal — an absent plural is just the empty list []), ! is inputs-only, and markers are banned on concept definitions, refines, structure fields, and package refs.

The runtime: one gate, three arms

The skip arm is the headline: it makes absence compose. You don't annotate the whole chain — the chain lifts itself, and every skipped pipe's output records an absence that points back at the origin:

Absence is a first-class record, never a null

There is no null Stuff. A slot with no value has an AbsenceRecord in the working memory's ledger: variable name, producing pipe, kind (skipped declared-absent not-provided), a human reason, and an upstream chain. Post-run reads use a tri-state accessor (resolve_stuff → value or record). A slot with neither a value nor a record is still a hard error: never-produced is a bug, not an absence.

The static safety net

The runtime story would be scary without the compile-time story. Validation now proves the absence safety theorem: a taint pass walks every controller's dataflow, computes per-slot presence (guaranteed vs maybe-absent), and rejects any flow where an absence could escape without an explicit sink.

CheckSeverityWhat it catches
optional_marker_invaliderrorGrammar misuse: X[]?, ! on outputs, markers on concepts/refines/fields.
optional_not_handlederrorA maybe-absent slot ends a sequence (or feeds a condition) without the controller declaring a ? output. Message names the origin, the propagation path, and three fixes.
optional_output_requirederrorA continue-reachable PipeCondition with a plain output — continue resolves the output absent, so a plain output would hide the no-output path. Breaking.
optional_branch_required_fielderrorA required structure field of a PipeParallel output fed by a maybe-absent branch.
optional_input_unguardederrorA template reference to a ? input without a guard (@?var, {% if var %}, inline is defined). Covers PipeLLM, PipeCompose, PipeCondition, PipeSearch, PipeImgGen templates.
optional_force_redundantwarningA ! whose slot is guaranteed present in every analyzed flow — dead assertion. Rides the new advisory warnings array (never flips is_valid), aggregated across flows so a ! that matters anywhere is never flagged.

The valid report also gains a liftable_pipes inventory: every pipe that may be skipped, with its trigger slots and absence source. That's what makes implicit lifting acceptable — authors see "may be skipped when X is absent" at /validate time, not by surprise in production.

Controllers under absence

continue now means "no output" — honestly breaking

Before: continue passed the current main stuff through, or errored when there was none — an untyped, invisible optional. Now: it records a declared-absent output (reason = the evaluated expression) and returns success, memory otherwise unchanged. The static rule forces such a condition to declare output = "X?", so downstream code knows.

Migration: the previous value stays in memory under its own name — consume it explicitly by that name (declared ? where it may be absent). The ergonomic replacement for pass-through is the phase-2 coalescing operator (??).

Dry-run parity: an all-special-outcomes condition records the same absence — except a fail-only condition (every outcome maps to fail), which raises in dry run too, since every live path can only raise.

Combine absorbs absence — by declared shape

  • Composite output: the absent component is simply omitted (a ledger note keeps observability).
  • Structured output, non-required field: the absence becomes the field default (None unless the author declared another default — per-field coalescing avant la lettre).
  • Structured output, required field: a typed runtime error naming the branch, the field, and the fixes — but this shape is already rejected statically by optional_branch_required_field, so the runtime guard is a belt-and-suspenders backstop.

Batch compacts

Absent branch results are dropped from the aggregated list. Batching a "keep or skip" condition over N items yields only the kept results — a list cannot hold a hole, so compaction is the only lossless behavior. The empty list [] is the whole absence story for plurals: a lifted pipe with a plural output writes a real empty ListContent (plus a ledger note), and taint stops there.

First-class on every surface

A run whose declared ? output resolves absent is a success everywhere — no surface treats it as an error or crashes on it:

  • Wire: main_stuff_name still names the declared slot; consumers branch on the absence record carried in the serialized memory (absences), never on transport. The ledger round-trips cross-process — a recorded absence no longer degrades to a hard miss after an API/worker hop.
  • Contracts: PipeInputContract/PipeOutputContract gain optional: bool, so tooling can see optionality without parsing the grammar.
  • CLI: pipelex run prints an explicit absence document; --save-main-stuff writes a main_stuff.json carrying "absent": true plus the provenance chain (and a markdown twin). The agent CLI returns the absence document as its result payload.
  • Graphs: nodes gain a skipped status with a skip_reason, and data edges fed by ? outputs carry optional: true — "why did my workflow produce nothing?" is now answerable from the execution graph.
  • Telemetry: OTel/Langfuse capture absence documents for both inputs and outputs.

The critical changes, as minimal diffs

1 — The lift gate (pipe_abstract.py): the trichotomy in four lines 
  presence_scan = await self.validate_before_run(...)   # raises for `!` (force) and for hard misses
+ if presence_scan.liftable:
+     # Implicit lifting (D3): a plain input fed a recorded absence skips the pipe;
+     # its output is recorded absent with provenance chaining to the input's record.
+     pipe_output = self._make_lifted_output(..., pipe_run_params=pipe_run_params)
  else:
      pipe_output = await self.live_run_pipe(...)  # or dry — unchanged

Inside _make_lifted_output, plurality is resolved with the exact rule the run path uses (declared multiplicity + invocation-level override), so a plural lift writes the real empty list downstream consumers were promised — singulars record the absence:

+ multiplicity_resolution = output_multiplicity_to_apply(
+     base_multiplicity=self.output.multiplicity,
+     override_multiplicity=pipe_run_params.output_multiplicity,
+ )
+ if multiplicity_resolution.is_multiple_outputs_enabled:
+     working_memory.set_new_main_stuff(empty_list_stuff, name=output_name)  # [] IS the plural absence
+     working_memory.record_absence(skip_record)          # observability note beside the value
+ else:
+     working_memory.record_new_main_absence(skip_record)  # the slot's resolution
2 — The ledger's two write modes (working_memory.py): NOTE vs RESOLUTION

This invariant pair is what keeps values and records from fighting. set_stuff pops any record under the written name (value supersedes record); the resolution write is its exact mirror.

+ def record_absence(self, record):            # NOTE: a value under the name is kept and wins
+     self.absences[record.variable_name] = record
+
+ def record_resolved_absence(self, record):   # RESOLUTION: mirror of set_stuff's invariant —
+     self.remove_stuff(name=record.variable_name)    # a stale value must not outrank
+     self.remove_alias(alias=record.variable_name)   # the fresh absence
+     self.record_absence(record)
3 — continue resolves the output absent (pipe_condition.py) breaking 
- # 'continue': deliver the current main stuff by passing it through
- # (raise PipeRunError when there is no main stuff to pass through)
+ # 'continue': the declared output resolves absent — memory otherwise unchanged
+ record = AbsenceRecord(
+     variable_name=output_name or MAIN_STUFF_NAME,
+     kind=AbsenceKind.DECLARED_ABSENT,
+     reason=f"expression '{evaluated_expression}' resolved to 'continue'",
+     producing_pipe=self.code,
+ )
+ working_memory.record_new_main_absence(record)

Paired with the static rule: a continue-reachable condition must declare output = "X?" (optional_output_required), so the no-output path is visible in the types.

4 — Parallel combine under absence (pipe_parallel.py), incl. the P1 the bots caught 
  branch_resolved = pipe_output.working_memory.resolve_main_stuff()   # tri-state, never raises on absence
+ if isinstance(branch_resolved, AbsenceRecord):
+     if not issubclass(structure_class, CompositeContent):
+         field_info = structure_class.model_fields.get(sub_pipe_output_name)
+         if field_info is not None and field_info.is_required():
+             raise PipeRunError(...)          # required field fed a hole — statically unreachable backstop
+     if self.add_each_output:                 # ← review round 1: parent slots exist ONLY under
+         working_memory.record_resolved_absence(branch_record)   #   add_each_output, same as present branches
+     continue                                 # omitted from the combine; non-required field → field default

The if self.add_each_output gate is the fix for the one P1 of the review round: without it, an absent branch wrote a resolved absence into the parent memory even when branch results aren't parent slots — deleting an unrelated same-named value. Present branches always had the gate; now both arms publish under the same rule.

Bonus — the load-bearing one-liner: StuffArtefact.__bool__

The guard idiom the lint recommends ({% if var %}, which @?var expands to) crashed on a present singular value: Jinja2's truth test fell through to the artefact's list-only __len__ and raised TypeError. Found by our own new contract fixture failing its dry run.

+ def __bool__(self) -> bool:
+     if isinstance(self._content, ListContent):
+         return bool(self._content.items)   # empty list is falsy (D4)
+     return True                            # a present singular is truthy

Why you can trust it

  • One commit per checkpoint, six checkpoints (A–F). Each ran the full gate set (make agent-check + full make agent-test) plus a context-free cold code review of the step diff by a fresh reviewer with no access to the plan or rationale. Findings were triaged every time: correctness fixed in-step, design tradeoffs recorded as deferred docs, over-engineering simplified.
  • TDD throughout: red tests first for every step — lift chains with provenance assertions, force-failure UX (the message must name the variable, both pipes, and the reason), plural normalization, hydration round-trips, end-to-end absent-main-output runs over every surface.
  • Review round 1 on the PR: 13 bot findings (greptile, cubic, Codex), each adversarially verified before acting — 9 confirmed and fixed (headline: the parallel parent-memory clobber P1), 1 dead-code deletion, 1 refuted with evidence, 1 already-deliberate design decision. All threads answered with commit citations; CI fully green.
  • Ground-truth fixtures: every spec-suite fixture's expectations were generated by running it against the real build before being written down — no guessed error categories.

What's deliberately NOT in phase 1

  • Coalescing ?? — the ergonomic replacement for continue pass-through. Phase 2. (Non-required parallel fields absorbing as their declared default is a small preview of it.)
  • The LLM maybe-wrapper — making ? on operator outputs change the LLM contract ("return nothing rather than invent"). Phase 2; over-claiming ? today is deliberately legal as evolution room, and deliberately not linted.
  • Cross-repo wave — mthds wire models carrying the absences ledger (which unblocks the hosted-API absent arm), mthds-ui rendering skipped nodes/optional edges, pipelex-api surfacing warnings + optional contract flags. Gated behind other in-flight work; no PRs yet.
  • Spec-suite de-gating — the suite's optionals coverage is written and validated live against this branch, but stays probe-skipped until both of its arms run an optionals-speaking pipelex (the HTTP arm pins the released pipelex==0.37.0).
