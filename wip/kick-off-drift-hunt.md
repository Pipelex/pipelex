# Drift Hunt — one-off full review of the hand-written docs

A campaign, not a feature: sweep every hand-written doc page for code↔doc drift, fix what's stale, and come out with per-section defect-density evidence. The drift-contracts system (see [wip/drift-contracts-design.md](drift-contracts-design.md), `docs/contribute/drift-contracts.md`) enforces the floor *going forward*; this hunt backfills the floor once. It was deliberately scoped out of the tool — it runs as a project instead.

## Cold-start context (update at every checkpoint)

- **Status:** PLAN WRITTEN — nothing started. Next = Stage 0.
- **Branch / worktree:** `docs/Update` in the `_docs` worktree (treat as repo root). Stage 2 fix batches may land as their own PRs — see Decision D4.
- **Working artifacts:** everything the hunt produces (pre-screen script, suspect list, findings) lives under `wip/drift-hunt/`.
- **Decisions taken:** D1–D6 below.
- **Open questions:** none blocking.

## Decisions

- **D1 — cocode is out of scope.** Not ready for this task (user call, 2026-07-05). The whole hunt runs on the pre-screen script + Claude agent fan-outs; do not reach for cocode even for sub-steps.
- **D2 — scope = hand-written pages under `docs/`.** Excluded as *generated*: `docs/errors/` (error reference pages, regenerated by `make gep`) and the generated gateway-models doc(s). Excluded as *freshly reviewed*: `docs/configuration/` and the CLI docs (`docs/tools/cli/` + `pipelex/cli/agent_cli/CLAUDE.md`) — they got a genuine review days ago as the drift-contracts seed acks; re-sweeping them now would measure nothing. Everything else under `docs/` is in: building-methods, features, cookbook, under-the-hood, tools (non-CLI), advanced, reliability, get-started, contribute, setup, viewpoint, index/license.
- **D3 — cookbook ground truth is a sibling repo.** `docs/cookbook/` pages reference examples that do NOT live in this codebase — they live in `../pipelex-cookbook`. Any agent reviewing a cookbook page must verify claims against `../pipelex-cookbook` (read-only), not conclude "referenced example missing" from this tree. The pre-screen's path-existence check must special-case `docs/cookbook/` the same way.
- **D4 — fixes land in reviewable batches.** One commit per docs section at minimum; separate PRs per section if a batch grows beyond comfortable review size. Default base: `dev`.
- **D5 — no manifest growth during the hunt.** The drift-contracts dogfood freeze stays in force: the hunt produces *evidence* for which sections might earn a contract later; it does not add contracts to `drift.toml`.
- **D6 — findings must survive adversarial verification before anything is fixed.** The failure mode of a big sweep is an agent confidently "correcting" a doc that was right. No finding is acted on unless a second, independent agent confirms it against the code with `file:line` evidence. Fix agents re-verify at fix time; a finding that doesn't hold up gets recorded as rejected, not silently dropped.

## What "drift" means here (and what it doesn't)

In scope per page: statements the code can contradict — commands, flags, config keys, defaults, file paths, API/class/function names, described behaviors and sequences, code snippets that should run or parse. Out of scope: editorial quality, tone, structure, SEO, completeness wishes ("this page should also cover X"). This is a drift hunt, not a rewrite; the standing repo rules apply to fixes (docs = current reality, no hardcoded counts, MkDocs conventions).

## Stage 0 — inventory + mechanical pre-screen

Deterministic checks that need no judgment, to make the semantic pass sharper and cheaper. The seed-ack dogfood showed this class is rich: several of its real catches (dead config section, phantom CLI flag, dead config field) were mechanically detectable.

- [ ] Build the inventory: every in-scope `.md` page (per D2), grouped by section, committed as `wip/drift-hunt/inventory.md` with a page count per section — this is the denominator for defect density later.
- [ ] Write the pre-screen script at `wip/drift-hunt/prescreen.py` (throwaway quality is fine — it's campaign tooling, not product; keep it self-contained, stdlib + repo venv only). Checks, each producing `(page, claim, verdict, evidence)` rows:
    - Referenced repo file paths exist in the tree (special-case `docs/cookbook/` → resolve against `../pipelex-cookbook`, per D3).
    - Mentioned config keys exist in `pipelex/pipelex.toml` / the `configs.py` model tree.
    - Mentioned `pipelex` / `pipelex-dev` CLI commands and flags exist in the actual `--help` surfaces.
    - Fenced `toml` blocks parse; fenced `python` blocks compile (`ast.parse`).
    - Internal doc links resolve (complementing, not re-implementing, the mkdocs strict build).
- [ ] Run it; triage the raw hits into `wip/drift-hunt/suspects.md` — per section: confirmed-mechanical defects vs needs-judgment flags vs false positives (note false-positive patterns; they tune Stage 1 prompts).
- [ ] Fix the confirmed mechanical defects immediately (they need no Stage 1) — one commit, gates: mkdocs strict build green.

### CHECKPOINT 0 — STOP (suspect list in hand)

Commit Stage 0 outputs + fixes; update Cold-start context. **User reviews `suspects.md` and the false-positive patterns, then decides the Stage 1 shape:** full fan-out over all in-scope sections vs worst-sections-first. Also sanity-check Stage 1's cost estimate against the observed page sizes before committing the fleet.

## Stage 1 — semantic review fan-out (the judgment work)

A multi-agent Workflow over the in-scope pages — requires the user's explicit go-ahead at Checkpoint 0 (fleet-scale token spend, plausibly on the order of millions of tokens; estimate concretely at Checkpoint 0).

- [ ] Per page, a review agent: read the page, extract its checkable claims, verify each against the current code (cookbook pages → `../pipelex-cookbook`, per D3), report findings with severity (`breaks-a-user` / `wrong` / `misleading` / `stale-detail`) and `file:line` evidence for both the doc claim and the contradicting code. Seed each agent with the page's Stage 0 suspect rows.
- [ ] Adversarial verify pass (D6): every finding independently re-derived by a verifier agent prompted to refute it; only confirmed findings survive. Run as a pipeline (page-review → verify per finding), not a barrier — sections should flow.
- [ ] Aggregate into `wip/drift-hunt/findings/<section>.md` (one file per section, findings ranked by severity) plus `wip/drift-hunt/findings/SUMMARY.md`: per-section counts, defect density (findings / pages), and the rejected-findings list with reasons.
- [ ] Log any observations relevant to the drift-contracts dogfood (e.g. "this section's drift is all mechanically detectable → derived-check candidate, not a contract") — they feed the Phase 3 verdict, per D5.

### CHECKPOINT 1 — STOP (findings, no fixes yet)

Commit findings; update Cold-start context. **Triage with the user:** confirm severity ranking, kill anything that smells like editorial creep (out of scope here), agree the fix order (default: by severity, then by section). This is a natural session handoff — Stage 2 needs no Stage 1 context beyond the findings files.

## Stage 2 — fix in batches

- [ ] Fix per section, working from `findings/<section>.md`, highest severity first. Each fix re-verified against the code at fix time (D6) — the finding is the pointer, the code is the authority.
- [ ] One commit per section; split into separate PRs against `dev` if a batch outgrows comfortable review (D4). Gates per batch: mkdocs strict build + `make check`.
- [ ] Note: fixing docs does NOT reopen drift contracts (docs are review targets, not triggers — only trigger files feed the ack digest). No ack churn expected; if a fix somehow touches a trigger file, resolve it with the `drift-review` skill as usual.
- [ ] Mark resolved findings in the findings files as batches land (mark, don't delete — the record is the campaign's audit trail until the final checkpoint).

### CHECKPOINT 2 — STOP (campaign close-out)

- [ ] All batches landed; mkdocs strict + `make check` green on the final state.
- [ ] Write the close-out in `findings/SUMMARY.md`: defect density per section, top defect classes, and the evidence-based shortlist of sections that might earn a drift contract (or a derived check) after the dogfood period — hand that shortlist to the drift-contracts Phase 3 verdict (TODOS.md), per D5.
- [ ] Prune `wip/drift-hunt/`: keep SUMMARY + inventory as the record; the per-section findings files and prescreen script can go once everything is landed.
- [ ] Update this file's Cold-start context to DONE.

## Out of scope (explicit)

- cocode, in any role (D1).
- Growing `drift.toml` (D5 — evidence now, contracts later).
- Editorial/style/structure rewrites, new content, SEO.
- Generated docs (`docs/errors/`, gateway models) — fix the generator if one of those is wrong.
- `docs/configuration/` + CLI docs (just reviewed via seed acks) — unless a Stage 1 finding elsewhere points back into them.
- Other repos' docs (the hunt reads `../pipelex-cookbook` as ground truth but does not fix it; cookbook-repo defects found along the way get listed in SUMMARY.md as a handoff).
