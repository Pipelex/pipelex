## 1. Test-module and test-class docstrings — a convention the repo does not actually hold

- **Reporter:** Codex, two threads — [`PRRT_kwDOOwmMFc6UetDk`](https://github.com/Pipelex/pipelex/pull/1069) on `tests/unit/pipelex/errors/test_error_identity_snapshot.py:1` and [`PRRT_kwDOOwmMFc6UetDn`](https://github.com/Pipelex/pipelex/pull/1069) on `tests/unit/repo/test_test_durations_paths.py:1`. Both ask for the module-level docstring to become comments or to be redistributed into the test methods, citing `AGENTS.md`: "Include concise docstrings explaining test purpose but **not on top of the file and not on top of the class**."
- **Verdict:** the rule says what Codex says it says. The repo does not follow it.
- **Measured on this branch:**
    - **579 of 1018** test modules open with a module-level docstring.
    - **436 of 1018** carry a docstring directly on the test class.
    - (For contrast, the sibling one-class-per-module rule in the same section *is* held — 978 of 1018 — which is why the class-splitting thread was fixed rather than deferred.)
- **The neighbours violate it too.** Every module adjacent to the two flagged files does the thing the rule forbids: `tests/unit/pipelex/cli/dev/test_check_keyword_only_cmd_fix.py`, `tests/unit/pipelex/cli/dev/test_subject_grant_registry.py` (its module docstring predates this PR) and `tests/unit/pipelex/cli/dev/conftest.py` all open with one. So conforming these two files would satisfy the letter of the rule while making them inconsistent with their own directory.
- **Why deferred:** this is not a defect in the PR, it is a rule/practice gap across the whole suite. Rewriting 2 files out of 579 does not close it — it just makes the two new files the odd ones out, and it costs the rationale its natural home (both docstrings explain *why the gate exists*, which is the most valuable thing in either file). Which way to resolve it is a repo-wide convention call, not something a PR-review pass should settle unilaterally.
- **Recommendation — pick one deliberately:**
    1. **Relax the rule to match practice.** Amend the pytest-standards source (`pipelex/kit/agent_rules/`, from which the root `AGENTS.md` / `CLAUDE.md` are generated) to allow a module-level docstring that explains *why the module exists*, keeping the prohibition on per-test purpose docstrings migrating upward. This matches what 57% of the suite already does and what the rule was probably reaching for.
    2. **Enforce it mechanically and sweep.** If the rule is meant, it needs a check — the same lesson this very PR is about: an invariant asserted in prose and gated by nothing drifts silently, and 579 files of drift is the proof. That means a guard plus a 579-file sweep, which is its own piece of work.
- **Note on the third new test file:** `tests/unit/pipelex/cogt/test_cogt_dependency_boundaries.py`, added by this same PR, opens with a `#` comment block rather than a docstring — i.e. the compliant form. Whichever resolution is taken, the three new files should end up consistent with each other.

## Not deferred — fixed on this branch

Recorded here only so all six threads are traceable:

- **The provider-edge gate missed a legal import form** (Greptile, `test_cogt_dependency_boundaries.py`). `_import_targets` recorded `from pipelex import providers` as a dependency on `pipelex`, so a `cogt → pipelex.providers` edge written that way never reached the golden-set assertion — the exact "reviewable diff" the test exists to force. Import targets now resolve an imported name to `base.name` when that names a module of this repo, and keep `base` when it is a symbol; the relative form (`from .. import providers`) is covered by the same path. Verified with a probe module: the edge is now reported. All five pinned rows and the ~20 `from pipelex import log` sites are byte-identical, because a symbol never resolves.
- **Two test classes in one module** (Codex, `test_subject_grant_registry.py`). `TestSubjectGrantRegistryOrder`'s tests merged into `TestSubjectGrantRegistry`; the colliding `test_missing_registry_is_an_explicit_error` renamed to `test_order_check_missing_registry_is_an_explicit_error`. Splitting into a sibling module was the alternative, but `_VALID_REGISTRY` and `_write_registry` are shared by both halves, so it would have cost a new `test_data.py` for three string constants.
- **The class docstring** (Codex, same file) — became a comment above the order tests, as a side effect of the merge above.
- **`--fix` never reported an out-of-order registry** (Codex, `check_keyword_only_cmd.py`). `_run_fix` returned before the order scan, so `make fko` on a scrambled registry printed "nothing to fix" while `make check-keyword-only` was about to fail — a false all-clear, and a contradiction of `docs/contribute/keyword-only-arguments.md`, which already groups `unsorted-grant` with the registry-level kinds "reported for a manual fix rather than rewritten" (the other two, `dead-grant` and `grant-param-mismatch`, do reach the report through `fix_all_violations`). The order result now joins the unfixable list. Verified end to end against a temporarily scrambled real registry: reported with its `subject_grants.toml:<line>` locator, still exiting 0 as the non-gating contract requires.
