# Deferred review findings from the instructor 1.17 and aiobotocore bump

Status: deferred. Each finding below came out of a `/rev` pass on `chore/Bumping` (items L-260927-56ef15 and L-260928-3a6683, with L-260927-61a69f for the aiobotocore swap), and each section says whether it was verified before it was deferred. An unverified finding rests on the reviewers' reading alone, and whoever picks it up should confirm it first.

## The Anthropic worker compares a structure method with `!=` (unverified)

Deferred in round 2 on L-260927-56ef15, at the `defects` bar, which fixes only confirmed defects that matter, so it was sorted as an improvement. Raised by cubic and Codex. `pipelex/providers/anthropic/anthropic_llm_worker.py`, in `_structure_method_kwargs`, tests `structure_method != StructureMethod.INSTRUCTOR_ANTHROPIC_REASONING_TOOLS` to decide whether to leave the tool choice to the model. The repository's standard is to branch on an enum with an exhaustive `match`/`case`, or through a property on the enum, so that adding a member forces someone to decide how it behaves here. As written, a new structure method silently takes the forced-tool-choice path. The suggested shape is a property such as `StructureMethod.forces_tool_choice`, or a `match` over the members that reach the Anthropic worker.

## Gemini tool mode validates structured output in lax mode (verified)

Deferred in round 2 on L-260928-3a6683, at the `defects` bar, on the developer's decision after a verifier confirmed it. Raised by the Codex adversarial reviewer.

**The defect.** `GoogleLLMWorker._validates_structured_output_strictly` in `pipelex/providers/google/google_llm_worker.py` returns `False` under `Mode.TOOLS`, and `_gen_object` passes that as `strict=`. instructor 1.17's `parse_genai_tools` (`instructor/v2/providers/genai/handlers.py`) validates the function-call arguments with `response_model.model_validate(obj=function_call.args, strict=strict)`, so the whole response goes through pydantic's lax Python-mode validation. Driven through `_gen_object` with a faked Gemini response and a schema of `count: int`, `enabled: bool` and an enum field, the payload `{"count": "001", "enabled": "off", "color": "red"}` was accepted after one call as `count=1, enabled=False`, with no schema re-ask. The same payload under `instructor/genai_structured_outputs` was rejected with `int_type` and re-asked.

**Why it went lax.** On `origin/dev`, instructor 1.15.1 validated this path strictly in Python mode, which refuses a string for an enum field, so every schema with an enum failed on Gemini tool calls, and so did ISO date strings. The branch went lax to fix that, and the looser handling of stringified scalars came with it.

**Its reach.** Lax mode only accepts strings that convert cleanly to the declared type, so a re-ask would have converged on the same value; the cost is that schema-nonconforming output skips the re-ask. The shipped `google.toml` now uses `instructor/genai_structured_outputs`, so tool mode is reached only by an older copied backend file that still names `instructor/genai_tools`, or by a per-model override.

**The fix, and why it was not done in the round.** Validating the tool arguments as strict JSON, `model_validate_json(json.dumps(args), strict=True)`, accepts enum strings, nested enums and ISO dates while rejecting `"001"` and `"off"`; instructor 1.17 already parses Anthropic tool calls that way. But instructor resolves its parse handler from a process-wide registry keyed by provider and mode (`instructor.v2.core.registry.mode_registry`), so the fix means registering a pipelex handler for `(Provider.GENAI, Mode.TOOLS)` over instructor's own, which changes the behaviour for every instructor genai client in the process, or asking instructor upstream to parse genai tool calls as JSON the way it does Anthropic's. One risk is unsettled either way: strict JSON rejects a float for an `int` field, which lax mode accepts, and without a live call it is unknown whether Gemini ever sends an integer argument as `1.0`. Whoever takes this should settle that with a live tool-mode call first, and add tests showing enum strings pass while stringified integers and booleans are rejected and re-asked.
