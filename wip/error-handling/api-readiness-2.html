Co-developer Briefing

API Readiness 2 — making errors usable on the wire

The follow-up to the error-handling overhaul. Same ErrorReport, now ready to cross the process boundary: a stable identity per class, an RFC 7807 renderer, a STRICT projection that's safe to publish, a total recovery path, end-to-end request_id, and structured errors on the delivery webhook.

branch feature/API-readiness-2  ←  dev
TL;DR for the busy reviewer.

Before this branch, ErrorReport was the in-process source of truth — but consumers (the API, the SDKs, the CLI) had to humanize class names, build their own HTTP envelopes, and branch on None when a Temporal failure crossed without a payload. After this branch:

  • Every PipelexError exposes a stable title() and type_uri() — auto-derived, always populated, dereferencing to a generated docs page.
  • ErrorReport.to_dict(disclosure_mode=…) and to_problem_document(…) give the API a single, framework-free RFC 7807 envelope with a STRICT projection that's safe to publish.
  • STRICT redaction is gated on message provenance, not inherited error_domain — a wrapper's internal text cannot leak through an INPUT cause.
  • recover_error_report() is now total: failures that cross Temporal without an embedded report synthesize an UnrecoverableWorkflowFailureError instead of returning None.
  • request_id rides on JobMetadata and lands on every Temporal log record via a per-invocation bound logger, not a ContextVar.
  • Failed runs carry a structured error object on the delivery webhook; reserved keys in WebhookTarget.payload are rejected at construction time.
  • Every PipelexError subclass now lives in exceptions.py / *_exceptions.py — enforced by an AST scan, discovered by a cached rglob at docs-generation time, and surfaced as a generated reference page.

Plan-of-record was the api-companion-revisions doc; the post-/review follow-ups landed as Phases 1-7 in TODOS.md. Stages 1-4 ship in this PR. Stage 5 (webhook signing) is a separate cross-repo track.

01Why this PR

The error-handling overhaul made ErrorReport the in-process truth. This PR makes it the on-the-wire truth.

The companion API team needed primitives the runtime did not yet expose. The original spec drafted them and was then re-scoped on a close read (see api-companion-revisions). Concretely, downstream consumers had to:

  • Humanize class names themselves. No title() on the error classes; the API, CLI, agent CLI, and future SDKs each rolled their own. Drift waiting to happen.
  • Build their own HTTP envelope. No to_problem_document(); ~30 lines of FastAPI Response wiring re-invented per consumer.
  • Choose a "strict" projection at the wrong layer. A safe-for-external-surface projection had no single source of truth.
  • Hand-author a fallback when recover_error_report returned None — every caller a copy of the same boilerplate, with a stringly-typed error_type that did not resolve to a real class.
  • Piggyback request_id on webhook.payload because nothing on JobMetadata carried it.
  • Get nothing structured on a failed run's webhook — only the run id and the failure status; the error stayed in worker logs.
The principle Pipelex owns the defaults. If a primitive has a sensible default — humanize a class name, kebab a class name, "an internal error occurred" placeholder — the default lives in pipelex and is returned as a populated value, not a None that consumers fill in. Total functions over partial ones. No speculative surface.

03PipelexError identity — title() and type_uri()

Every error class becomes a first-class entry in a stable, documented namespace.

Two classmethods on PipelexError, both total — they always return a populated str. Auto-derived from the class name; a subclass overrides only when the default is wrong by declaring _declared_title or _declared_type_uri directly in its own body. Inheritance is intentionally bypassed via cls.__dict__.get(…) — a parent's curated title does not silently capture every subclass.

pipelex/base_exceptions.py — the two new classmethods
class PipelexError(Exception):
    _declared_title: ClassVar[str | None] = "Pipelex error"
    _declared_type_uri: ClassVar[str | None] = None

    @classmethod
    def title(cls) -> str:
        # Read only the class's OWN body — a curated title is never inherited.
        declared = cls.__dict__.get("_declared_title")
        if isinstance(declared, str):
            return declared
        return _humanize_class_name(cls.__name__)

    @classmethod
    def type_uri(cls) -> str:
        declared = cls.__dict__.get("_declared_type_uri")
        if isinstance(declared, str):
            return declared
        return f"{URLs.error_docs_base}/{pascal_case_to_kebab(cls.__name__)}/"

Both values are populated on every ErrorReport as required string fields — consumers read report.title / report.type_uri directly. No humanize helper to keep in sync, no kebab helper, no "is this None?" branch.

Classtitle()type_uri()
PipeOperatorRetryError "Pipe operator retry" …/errors/pipe-operator-retry-error/
LLMCompletionError "LLM completion" (acronym preserved) …/errors/llm-completion-error/
UnrecoverableWorkflowFailureError "Unrecoverable workflow failure" …/errors/unrecoverable-workflow-failure-error/
Pure function type_uri() reads only the URLs.error_docs_base constant — safe to call before Pipelex boot, safe inside Temporal workflow code, no determinism hazard. The earlier ErrorManager indirection (and the [errors_config] block) was removed for exactly this reason: a mutable read of the base URI would have leaked into workflow history.

04ErrorReport as a Pydantic BaseModel

A small conversion that unlocks the Temporal data-converter path.

ErrorReport was a frozen Pydantic dataclass. We needed it to cross the Temporal activity boundary as a typed field on DeliveryActivityArg — like every other field on that arg — instead of as a dict shim with a _dict suffix telegraphing the implementation detail. The already-shipped BaseModelPayloadConverter._unwrap_optional_base_model handles BaseModel | None directly; teaching it to round-trip Pydantic dataclasses generically would have been a much larger diff for the same end.

pipelex/base_exceptions.py — dataclass → BaseModel
@dataclass(frozen=True, config=ConfigDict(extra="forbid", arbitrary_types_allowed=True))
class ErrorReport:
class ErrorReport(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", arbitrary_types_allowed=True)

    error_type: str
    message: str
    title: str
    type_uri: str
    error_category: str | None = None
    error_domain: str | None = None
    retryable: bool | None = None
    user_action: UserAction | None = None
    model: str | None = None
    provider: str | None = None
    provider_metadata: ProviderErrorMetadata | None = None
    caller_facing_message: bool = False
Behavioral note An attempted mutation now raises pydantic.ValidationError instead of dataclasses.FrozenInstanceError. Anyone catching the specific dataclass error gets a surprise — tests updated to match. to_dict uses self.model_dump(exclude_none=True); from_dict uses cls.model_validate(data).

05DisclosureMode and the RFC 7807 envelope

One enum, two projection methods. The single source of truth for "what does strict mode hide".

Two methods on ErrorReport, both parameterized by a DisclosureMode: to_dict(disclosure_mode=…) projects the same report, and to_problem_document(…) renders it as an RFC 7807 application/problem+json envelope. The runtime stays HTTP-agnostic — both return plain dicts; no FastAPI/Starlette import.

pipelex/base_exceptions.py — the new public surface
class DisclosureMode(StrEnum):
    VERBOSE = "verbose"
    STRICT = "strict"

class ErrorReport(BaseModel):
    def to_dict(self, disclosure_mode: DisclosureMode = DisclosureMode.VERBOSE) -> dict[str, Any]: ...
    def to_problem_document(
        self,
        *,
        instance: str | None = None,
        request_id: str | None = None,
        disclosure_mode: DisclosureMode = DisclosureMode.VERBOSE,
    ) -> dict[str, Any]: ...

STRICT redaction rule

Keys kept in all modes (stable identifiers, never sensitive): error_type, error_domain, error_category, retryable, title, type_uri. STRICT then projects the rest:

Why provider_metadata isn't fully dropped under STRICT. Two fields on it — status_code and retry_after_seconds — are actionable client hints, not provider attribution: the HTTP adapter needs status_code == 429 to surface a Retry-After header from the same payload. We keep that curated slice and drop everything else (provider_error_code, body, request_id).

A typical STRICT projection (illustrative)
{
  "error_type": "LLMCompletionError",
  "error_domain": "runtime",
  "error_category": "transient",
  "retryable": true,
  "title": "LLM completion",
  "type_uri": "https://docs.pipelex.com/latest/errors/llm-completion-error/",
  "message": "An internal error occurred.",        // placeholder — provenance != caller-facing
  "provider_metadata": {
    "status_code": 429,                                        // kept — actionable
    "retry_after_seconds": 12                                  // kept — actionable
  }
}

The RFC 7807 envelope

to_problem_document maps the 7807 slots from the report (type ← type_uri, title ← title, status ← http_status, detail ← message after redaction), then rides the Pipelex-native fields as extension members. The downstream HTTP adapter wraps the dict in its framework's response shape — that's its 10 lines, not 30.

06STRICT keyed on provenance, not error_domain

The post-/review fix. STRICT got two leak vectors right at landing; this gates both.

The bug STRICT originally let message through when error_domain == INPUT — the assumption being "INPUT reports describe the caller's own data, so the wording is safe to echo". But error_domain is inherited up the __cause__ chain by _enrich_error_report_from_cause. So:
  • A domain-less wrapper (e.g. PipelexUnexpectedError) raised from an INPUT-domain cause inherited the cause's domain and leaked its own (non-caller-facing) message through STRICT.
  • to_problem_document(STRICT) echoed provider / model / provider_metadata for INPUT reports regardless of whether they originated in a provider call.

The fix gates STRICT on where the message came from, not on a classification that gets passed up the chain. A new per-class ClassVar opts the class in:

pipelex/base_exceptions.py — the provenance flag
class PipelexError(Exception):
    # True when this class authors caller-facing copy. STRICT keeps `message`
    # and `user_action` verbatim for flagged classes; redacts for every other.
    # Inherits normally — subclasses of a caller-facing error stay caller-facing.
    _authors_caller_facing_message: ClassVar[bool] = False

class ErrorReport(BaseModel):
    # Set at construction from `PipelexError._authors_caller_facing_message`.
    # Wrapper-wins: never inherited from the __cause__ chain, since it tracks
    # the provenance of `report.message` (always the wrapper's own message).
    caller_facing_message: bool = False

Only the error classes whose message is genuinely caller-facing copy opt in — text describing the caller's own input rather than internal state. Today that's PipelexInterpreterError (.mthds syntax / semantics) and ValidateBundleError (bundle-level validation). Everything else has its message replaced with the generic "An internal error occurred." placeholder under STRICT.

The same fix unconditionally drops provider and model under STRICT, regardless of domain. provider_metadata goes through the curated slice above.

07Total recover_error_report + UnrecoverableWorkflowFailureError

Removes the "caller hand-authors a fallback report" duplication pattern at every downstream site.

The original spec had recover_error_report(exc) -> ErrorReport | None. Each caller (the API submitter, the CLI on async result, anyone landing later) would then duplicate the same fallback boilerplate — an ErrorReport(error_type="WorkflowFailureUnrecoverable", …) with a stringly-typed error_type that didn't resolve to a real class, couldn't carry an auto-derived type_uri, and couldn't be matched on by pattern.

We turned it into a total function. When the Temporal failure chain carries no embedded report — a non-Pipelex exception, a worker crash, a heartbeat timeout, anything that crossed without going through the activity bridge — it synthesizes one from a new error class.

pipelex/temporal/tprl/temporal_error.py — total signature, single fallback class
def recover_error_report(exc: BaseException) -> ErrorReport | None:
def recover_error_report(exc: BaseException) -> ErrorReport:
    report_dict = _find_error_report_dict(exc)
    if report_dict is not None:
        return ErrorReport.from_dict(report_dict)  # could raise ValidationError
    return None
        try:
            return ErrorReport.from_dict(report_dict)
        except ValidationError:
            # Internal contract bug — but we still need to deliver the failure
            # webhook. Surface it via the same fallback class with a marker on
            # the message so the bug stays visible on the wire.
            recovered = report_dict.get("message")
            recovered_msg = recovered if isinstance(recovered, str) and recovered.strip() else _message_from_exc(exc)
            fallback = f"{recovered_msg} {_ERROR_REPORT_VALIDATION_FAILED_MARKER}"
            return UnrecoverableWorkflowFailureError(fallback).to_error_report()
    return UnrecoverableWorkflowFailureError(_message_from_exc(exc)).to_error_report()

The new UnrecoverableWorkflowFailureError (pipelex/temporal/exceptions.py) is a real PipelexError subclass — it has a type_uri that resolves to a generated doc page, a stable identity, and shows up in the registry like every other class. Callers in workflow_caller.py dropped their three if error_report is not None branches.

_message_from_exc walks the __cause__ chain and surfaces the deepest non-empty message — not the outer "Workflow execution failed" generic, which would defeat diagnostic intent. There's a cycle guard (id(node) set) and a repr(exc) fallback when every node has an empty message.

Behavioral change at the no-report path WorkflowExecutionError.message on the no-report path changes from the Pipelex-framed "Failed to execute workflow X" to the synthesized _message_from_exc(exc) text — strictly more diagnostic. The legacy framing remains on the WorkflowAlreadyStartedError / RPCError / non-ApplicationError-cause paths (those don't call recover_error_report).

08request_id end to end

From X-Request-ID at the API edge to every Temporal log record on the worker.

The companion API needed a correlation id that survives the Temporal serialization boundary. The candidate was a ContextVar — same pattern as session_id elsewhere — but a ContextVar is process-local: it does not cross the activity/workflow serialization boundary in a distributed worker topology. So request_id lives on JobMetadata instead, threaded explicitly into the per-invocation log binding.

pipelex/pipeline/job_metadata.py
class JobMetadata(BaseModel):
    pipeline_run_id: str
    session_id: str | None = None
    user_id: str | None = None
    request_id: str | None = None  # caller-supplied (e.g. X-Request-ID at the API edge)

On the worker side, the two log helpers gained a shared base that builds the right extra dict on every severity call:

pipelex/temporal/log_temporal.py — bound logger adapter
class _RequestIdLog:
    """Per-invocation Temporal log helper bound to a request_id."""

    _logger: ClassVar[Any]  # workflow.logger or activity.logger

    def __init__(self, request_id: str | None = None) -> None:
        self._request_id = request_id

    def _build_extra(self) -> dict[str, str] | None:
        if self._request_id is None:
            return None
        return {"request_id": self._request_id}

    def info(self, content): self._logger.log(logging.INFO, content, extra=self._build_extra())
    # … debug / warning / error / critical / verbose / dev — same shape

class WorkflowLog(_RequestIdLog):
    _logger: ClassVar[Any] = workflow.logger

class ActivityLog(_RequestIdLog):
    _logger: ClassVar[Any] = activity.logger

WfPipeRun / WfPipeRouter build a WorkflowLog(request_id=job_metadata.request_id) at entry; every log call from that invocation lands the id automatically via the extra dict — no call-site threading, no kwarg to forget. The module-level workflow_log / activity_log singletons stay unbound for call sites that have no job_metadata in scope (e.g. TemporalError's severity logs).

The same request_id also crosses the direct-mode boundary: PipeRun forwards it to DeliveryExecutor so the webhook delivery log line carries the originating id even when there's no Temporal involved.

09Webhook payload + reserved-key guard

A failure on the wire now carries a structured error; a static payload can't silently shift meaning with delivery status.

On a failed run, DeliveryExecutor threads the ErrorReport into _notify_webhook, which adds an error key to the outgoing body. Receivers rehydrate losslessly via ErrorReport.from_dict(payload["error"]) — and the API then chooses its own disclosure at its own surface via to_problem_document(disclosure_mode=STRICT). The webhook stays VERBOSE because the URL is caller-supplied: the receiver already owns the run and its data.

pipelex/pipe_run/delivery_executor.py
class DeliveryExecutor:
    async def execute(
        self,
        ...,
        error_report: ErrorReport | None = None,
        request_id: str | None = None,
    ) -> None:
        ...
        await self._notify_webhook(pipeline_run_id, status, result_url, webhook,
                                   error_report, request_id=request_id)

    async def _notify_webhook(self, ..., error_report, request_id=None) -> None:
        payload = dict(webhook.payload)            # caller's static payload
        payload["pipeline_run_id"] = pipeline_run_id
        payload["status"] = status
        payload["result_url"] = result_url
        if error_report is not None:
            payload["error"] = error_report.to_dict(disclosure_mode=DisclosureMode.VERBOSE)

That writes four Pipelex-owned keys on top of the caller's static payload. If a caller registers a WebhookTarget whose payload already declares one of those keys, its value silently shifts with delivery status — a static "status": "ok" at registration becomes "status": "FAILED" on the failure delivery. We reject the collision at construction time instead:

pipelex/pipe_run/delivery_assignment.py — reserved-key validator
_RESERVED_WEBHOOK_PAYLOAD_KEYS: frozenset[str] = frozenset({
    "pipeline_run_id", "status", "result_url", "error",
})

class WebhookTarget(BaseModel):
    url: str
    headers: dict[str, str] = Field(default_factory=dict)
    payload: dict[str, Any] = Field(default_factory=dict)

    @field_validator("payload", mode="after")
    @classmethod
    def _reject_reserved_keys(cls, value: dict[str, Any]) -> dict[str, Any]:
        collisions = set(value) & _RESERVED_WEBHOOK_PAYLOAD_KEYS
        if collisions:
            msg = (
                f"WebhookTarget.payload contains reserved keys: {sorted(collisions)}. "
                "Pipelex owns these keys (assigned per delivery); choose different names."
            )
            raise ValueError(msg)
        return value

Loud failure at construction; no surprise at delivery time.

10Per-class doc pages + filename convention

Every type_uri dereferences to a real page. Every PipelexError subclass shows up by construction.

A new pipelex-dev generate-error-pages command writes one Markdown page per PipelexError subclass to docs/errors/<kebab-class-name>.md, plus a landing docs/errors/index.md grouped by top-level PipelexError branch. Each page carries the class identity table (error_type, title, type_uri, error_domain, defining module, parent-class link, class-level user_action when declared), a docstring fragment, and a back-link to the Error Model overview. Generated pages are stamped <!-- pipelex:generated -->; maintainers can claim a page for hand-editing by adding <!-- pipelex:authored --> and the generator preserves it across runs.

The discovery problem

Discovery has to enumerate every subclass — including those whose home module is only reached via a deferred import path (every plugin worker / factory: anthropic, bedrock, gateway, google, mistral, openai/vertex, azure, portkey, plus standalone classes that ship under extras). The earlier registry-with-allowlist pipelex/errors/error_module_registry.py was a drift magnet — and got drift wrong: a spot check found ~20 classes invisible to it.

We replaced the registry with a filename convention + a cached rglob, gated by tests on both sides:

The convention test runs an AST scan over the package, picks out every class whose transitive base resolves to PipelexError, and asserts each file matches exceptions.py or *_exceptions.py (the root pipelex/base_exceptions.py is special-cased). A new class in the wrong file fails CI. A backstop test then walks PipelexError.__subclasses__() after the force-load helper runs and asserts the runtime set equals the AST set — so a class whose home module isn't reached by the rglob (or vice versa) fails CI too.

Net effect: adding a new error class is a one-step operation — write it in a properly-named module. No manifest to update, no allowlist to maintain.
