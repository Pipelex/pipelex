# Phase 2 plugin-seam review — deferred items

Items surfaced by the xhigh `/code-review` pass over the current PR (the inference-backend plugin seam + all four migrated families: LLM/ImgGen/Extract/Search). These are latent footguns reachable only by external entry-point plugins or not-yet-written callers, plus quality cleanups — none produces wrong output on a live path today, so they were intentionally NOT changed and are left here for later triage.

The three CONFIRMED pre-merge gaps from the same pass were fixed in this PR (import-light blocklist completeness, structured lookup-miss error, multi-spec `require_sdk` naming); only the items below remain.

## Latent footguns — decide at the Phase 3 staging boundary whether to gate or document

- **`build_registrar` silently drops three of the five registrar collections.** `pipelex.py` `build_registrar` accumulates `cli_commands` / `slot_claims` / `teardown_callbacks`, but boot only consumes `inference_backends` and `orchestrators`. An external `pipelex.plugins` entry-point plugin that calls `add_cli_command` / `claim_pipe_run` / `add_teardown` registers with no error and shows up in `pipelex plugins list`, yet its command never appears, its hub slot is never wired, and **its teardown never runs at `Pipelex.teardown()`** — any SDK client / external resource it opened leaks for the process lifetime. The discovery + iteration path is fully live, so this is reachable today by a third-party plugin; only the in-tree builtins (which use none of those three menus yet) keep it latent. At minimum, boot should warn on an unconsumed contribution rather than silently ignore it; better, wire the three collections as the orchestrator seam lands in Phase 3.

- **`make_search_worker` can silently drop usage reporting.** `cogt/search/search_worker_factory.py` moved `reporting_delegate` from an unconditional in-factory `get_report_delegate()` fetch to a parameter that **defaults to `None`**. The single production caller (`search_generate.py`) passes it, but any future caller (a Temporal search-activity path, a host runtime, a test) that omits it gets a search worker emitting no usage/cost report — silent zero where the old code always reported. The other three families route their delegate the same way, but search is the one whose factory previously self-fetched, so it is the regression-prone one. Consider making the param non-defaulting (force the caller to decide) or fall back to `get_report_delegate()` when `None`.

- **A callable plugin *instance* is mistaken for a factory.** `plugins/discovery.py` `_load_external_plugin` uses `loaded() if callable(loaded) else loaded`, which will **call** a plugin object whose class defines `__call__` instead of using it as the plugin. If that `__call__` returns `None` or raises, a valid installed plugin is rejected as `BrokenPluginError` with a confusing "failed to load entry point" message. Tighten the factory-vs-instance discrimination (e.g. accept only a class or a plain function as a factory, not any `callable`). Only reachable via an external entry point, so latent until the discovery path has real out-of-tree consumers.

- **The coverage test leans on an unenforced contract.** `tests/unit/pipelex/plugins/test_inference_backend_coverage.py` constructs `PluginRegistrar(config=cast('PipelexConfig', None))` and calls each builtin's `register()`, relying on the invariant that `register()` never reads `self.config`. If a future builtin reads `registrar.config` (a plausible mistake — `config` is an `__init__` param), the test crashes with `AttributeError: 'NoneType'` on a path unrelated to the change under test, masking the real registration logic behind a confusing CI failure instead of a clear contract violation. Either pass a minimal real/stub config, or make the contract explicit (assert/typed null-object) so a violation fails loud and on-point.

## Quality cleanups — fold into the Phase 3 seam threading

- **Redundant `ModelHandle` double-construction.** Already captured in [`phase-1-review-deferred.md`](phase-1-review-deferred.md) (item 1): each family factory builds a `ModelHandle` only to read `.sdk` for the lookup, then every `_make_*_worker` closure rebuilds the identical handle from the same `inference_model`. Disappears for free if a later phase threads `model_handle` through the `MakeWorkerFn` signature; not worth a seam-signature change on its own. Cross-referenced here because the xhigh pass re-surfaced it across all four families and ~two dozen closures.

- **Copy-pasted worker-builder preamble.** The `model_handle = ModelHandle.make_for_inference_model(...)` + `sdk_clients.get_or_create(handle=..., build=lambda: ...)` dance repeats across ~two dozen `_make_*_worker` closures (`google_plugin.py`, `bedrock_plugin.py`, the openai/gateway/portkey families, …), varying only in the build lambda and the worker constructed. A shared helper — `build_cached_client(inference_model, *, sdk_clients, build) -> (model_handle, sdk_instance)` — would shrink each closure to its build lambda plus the worker call, and localize any future change to client caching / handle derivation / teardown registration. (Composes naturally with threading `model_handle` through `MakeWorkerFn` above.)

- **Duplicate img-gen worker builders on the OpenAI-completions substrate.** `_make_openrouter_img_gen_worker` (`openrouter_plugin.py`), `_make_blackboxai_img_gen_worker` (`blackboxai_plugin.py`), and the gateway-completions img-gen variant are the same closure — `OpenAIClientFactory.make_openai_client` → `get_or_create` → `OpenAICompletionsImgGenWorker(...)` — differing only in the completions-factory subclass and the `is_http_url_enabled` flag. The same shape recurs across the gateway/portkey/openai `_make_*_completions_worker` LLM closures. Parameterize on the factory class so a substrate fix lands in one place.

- **Search rebuilds its worker on every call.** `cogt/content_generation/search_generate.py` (`search_gen_sourced_answer` / `search_gen_structured`) constructs a fresh `SearchWorker` per search call — re-resolving model + backend, re-running the registry lookup, and (for the linkup arm) re-probing `importlib.util.find_spec` — where LLM/img_gen/extract return a worker cached in `InferenceManager`. The SDK client itself is cached in `SdkClientRegistry`, but the worker rebuild + resolution + `find_spec` repeat. The per-call `find_spec` on the linkup search arm is **new in this PR** (the migration routed search through `require_sdk`). Cache the search worker per handle the way the other three families do.

- **Dead `self.model_handle` field on `AzureImgGenWorker`.** `plugins/azure_rest/azure_img_gen_worker.py` `__init__` stores `self.model_handle` and reads it exactly once on the next line to re-resolve the backend via `get_models_manager()` — then never references it again. Leftover per-instance state from the `Plugin` → `ModelHandle` rename; the factory already resolved the backend and could hand it over directly, and the test fixtures had to set `worker.model_handle = MagicMock()` purely to satisfy construction. Drop the field and the redundant hub re-resolution; have the factory pass the `InferenceBackend` it already fetched.

- **Missing `-> None` return annotations.** `plugins/sdk_client_registry.py` `teardown` (and `setup` / `teardown` in `sdk_client_manager.py`) omit the `-> None` return annotation, against the "every function return must be typed" standard. Pyright in `make agent-check` does not flag missing return annotations by default, so it passes CI silently. Carried verbatim from the deleted `plugin_sdk_registry.py` / `plugin_manager.py` during the rename — a pre-existing untyped shape, not newly authored. Low cost, no runtime consequence; annotate when these files are next touched.
