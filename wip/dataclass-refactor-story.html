Data holders got the right shape — and the Temporal wire learned a new one

We removed every stdlib @dataclass from pipelex/, replacing each with the lowest-churn correct form per site instead of blanket BaseModel. The enabling change: the Temporal payload converter now serializes pydantic dataclasses with full type preservation, not just BaseModel.

refactor/Dataclasses → dev PR #949 kajson 0.5.0 → 0.6.0 9 prod files · 3 new test suites

Two results to take away:

  1. A rule for picking a data-holder shape (the decision tree below) — use it whenever you add or convert one.
  2. A widened Temporal converter — pydantic dataclasses are now wire-legal, with the existing BaseModel path byte-for-byte unchanged.

Picking a shape

No stdlib @dataclass survives in pipelex/. The easy fix would be to make everything a BaseModel — we deliberately didn't. We use four forms, picked by which capabilities the site actually needs:

FormWire-legalCapabilities we leverageWe use it for
NamedTuple ✗ Named fields, immutable, positional-unpack compatible, and zero validation (so it can hold a bare Protocol or arbitrary type), no pydantic overhead. Small fixed records replacing bare tuples; holders of a @runtime_checkable Protocol or other non-pydantic field.
pydantic dataclass ✓ Dataclass idioms — field(default_factory=…), computed @property, frozen= — plus validation/coercion on construction. No model_dump / model_validate. Internal records that are built + field-read but never serialized. Lowest-churn swap from a stdlib @dataclass (just the decorator).
frozen BaseModel ✓ The full model API (model_dump, validators, discriminated unions), immutability, hashability, and — crucially — being type-distinct from tuple. Immutable value objects that need the model API, sit in a uniformly-BaseModel layer, or must not be mistaken for a tuple in a union.
mutable BaseModel ✓ The full model API and in-place field mutation. Objects genuinely mutated in place that also want the model API or layer consistency. (Else a non-frozen pydantic dataclass is lighter.)

The deciding question is the Wire-legal column crossed with "does it need the model API / serialization?" — the tree below walks exactly that:

The Temporal converter change

pipelex/temporal/temporal_data_converter.py defines BaseModelPayloadConverter — the class Temporal calls to turn every workflow/activity argument and return value into bytes, and back. Pipelex sends selected values through kajson instead of Temporal's stock JSON, because kajson stamps each object with its __class__ / __module__ so the receiver rebuilds the exact Python class. Stock JSON would hand back a plain dict and lose the type.

What changed: the set of values that take the kajson lane. Before, only BaseModel, Optional[BaseModel], and list[BaseModel] qualified. Now pydantic dataclasses (and Optional / list of them) qualify too. The BaseModel lane is unchanged.

Two directions, two checks

Serialization holds the actual value; deserialization holds only the declared type hint. So the same question is asked two ways:

  • to_payload asks _is_kajson_wire_value(value) = isinstance(value, BaseModel) or is_pydantic_dataclass(type(value)).
  • from_payload asks _is_kajson_type(type_hint) — the same test one level up — and reuses it for the scalar, Optional[X], and list[X] shapes.

The old code inlined the BaseModel checks and duplicated the payload/metadata building across the scalar and list branches. We factored that into _kajson_to_payload + _first_kajson_list_element, then added the dataclass arm behind the BaseModel short-circuit so the hot path is untouched:

@classmethod
def _is_kajson_wire_value(cls, value: object) -> bool:        # used by to_payload (has the value)
    return isinstance(value, BaseModel) or is_pydantic_dataclass(type(value))

@classmethod
def _is_kajson_type(cls, type_hint: Any) -> bool:            # used by from_payload (has the hint)
    if isinstance(type_hint, type) and issubclass(type_hint, BaseModel):
        return True
    return is_pydantic_dataclass(cast("Any", type_hint))     # safe (False) on non-class hints

Two guarantees

BaseModel path is byte-identical — locked by a regression test that asserts a BaseModel payload's metadata and bytes are exactly what the old code produced. And it's strictly safer: the old list branch called issubclass(args[0], BaseModel) directly, which raised on a non-class arg like list[list[int]]; _is_kajson_type guards with isinstance(.., type) first.

The receiving half is in kajson itself (bumped 0.5.0 → 0.6.0): a new decode branch calls is_pydantic_dataclass(cls) and reconstructs via cls(**data) — running the validator and raising loudly on bad input, instead of the old untested catch-all that silently returned a raw dict.

Three things worth knowing

A NamedTuple is a tuple

RegistrationFailure is returned as RegistrationFailure | tuple[str, ...] and callers do isinstance(x, RegistrationFailure). A NamedTuple would also satisfy isinstance(x, tuple), blurring the two arms — so it's a frozen BaseModel, which is cleanly not-a-tuple. Whenever a value is returned in a union beside a real tuple, model it.

DispatchOptions stays importable without temporalio

It holds a live temporalio RetryPolicy, but temporalio is an optional extra. A bare forward ref imports but blows up (PydanticUserError) on construction. The fix is a runtime placeholder so the field resolves to Any without importing temporalio:

 if TYPE_CHECKING:
     from temporalio.common import RetryPolicy   # type checkers see the real class
+else:
+    RetryPolicy = Any                            # runtime: no import, no validation
Don't convert the wire BaseModels

The widening makes pydantic dataclasses legal on the wire; it does not motivate converting the types already there (PipeJob, PipeOutput, WorkingMemory, Stuff, the StuffContent union, GraphSpec, …). They stay BaseModel — they need discriminated unions, model validators, and the dynamic-class mechanism. A NamedTuple or stdlib dataclass on the wire silently corrupts distributed execution.
