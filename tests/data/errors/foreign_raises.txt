# The raises, in pipelex/ and api/pipelex_api/, of a class outside the PipelexError root that are right as they are.
#
# Each line is `path | function | exception | disposition`, one per raise site, so a function raising the same class
# twice is listed twice. tests/unit/pipelex/errors/test_foreign_raises.py fails on a foreign raise this file does not
# list and on a listed one that is gone. The dispositions:
#
# - invariant: a builtin raised only on a bug of ours, which a boundary reports as runtime.unexpected;
# - validator: a builtin raised in a helper only pydantic validators call, which pydantic wraps;
# - private: a private class caught in the module that defines it, which no reader sees;
# - carrier: a class a library or protocol expects by type (the import system's ImportError, httpx's transport
#   errors, the standard's method tree refusal its callers translate, the Jinja2 SecurityError the template sandbox
#   stops a render with) that the scan cannot recognise by its name alone;
# - tooling: developer or release code outside the exempt directories, which only the development CLI calls;
# - caught: a builtin raised in a module that must import nothing of Pipelex, which its every caller catches by type.
#
# A new raise belongs here only when it is one of these; otherwise raise a coded PipelexError subclass.
