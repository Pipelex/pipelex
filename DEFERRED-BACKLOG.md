## Top priorities

Highest-leverage open work, pulled to the front. The bug-kind entries here were re-verified against the code (see [BUG-VERIFICATION.md](BUG-VERIFICATION.md)); two former "high" bugs were dropped — one stale, one already shipped.

- **Cross-worker cost report assembly is silently missing (bug, verified — medium).** The cross-worker assembly wiring is missing: `UsageAggregator.aggregate` and `ReportingManager.inject_tokens_usages` exist but have zero production callers — so the `generate_report` call at run completion (`pipelex/cli/commands/run/_run_core.py:224`) reports only from the local `_usage_registries` and never sees the distributed `UsageReportEvent`s. The graph-assembly path reads events but never feeds them through `UsageAggregator → inject_tokens_usages` before `generate_report` runs. This is the single biggest functional gap. See *Distributed tracing & cost reporting*.
- **Replay-determinism: `get_config()` reads inside workflow code (bug, verified — real but deferred by design).** Workflow-side paths (`content_generator_in_workflow.py` make_* methods, `observability.py:104`) read live config at runtime. Any config edit between a workflow start and its replay produces a different Temporal command and a `NondeterminismError`. The cluster-grade fix is Worker Versioning; a search-attribute snapshot on `JobMetadata` is the cheaper interim. See *Temporal primitives, IDs & determinism*. The submitter-snapshot fix was deliberately reverted; track as known-deferred (drain-before-config-edit + future Worker Versioning), not a fresh fix.
- **Rate limiting: no per-(provider, model) limiter (enhancement, high).** `max_concurrency` bounds concurrency but providers enforce RPM/TPM; a high-concurrency batch of fast calls blows a provider tier instantly. Needs a direct-mode token-bucket gate at the single inference call site plus Temporal task-queue limits. See *Concurrency, batching & rate limiting*.
- **Cross-package deps don't ship in the crate (high).** `_load_single_dependency` parses dependency blueprints but never accumulates them into `self._blueprints`, so the crate excludes all dependency content and cross-package pipelines fail on Temporal workers unless packages are pre-installed on PIPELEXPATH. This is the Phase 6a keystone, with no integration test proving a self-contained crate. See *Crate / dependency architecture*.
- **Webhook signing not implemented anywhere (security, high).** The whole 3-step rollout (receiver dual-format verification → worker body-bytes signing → drop legacy fallback) is unshipped; `_notify_webhook` currently posts with no body HMAC at all. Cross-repo lockstep with `pipelex-api`; needs Louis's green light. See *Webhook signing & delivery security*.

> Verified stale/shipped, removed from priorities: **PipeLLM defeats retry** (stale — the router transient-retry loop was removed; direct mode is single-attempt by design, Temporal derives retryability from the cause chain) and **bare `except Exception` in `wf_pipe_router`** (already shipped, PR #943). See [BUG-VERIFICATION.md](BUG-VERIFICATION.md).
